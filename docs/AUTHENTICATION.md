# 账号与认证

下载器与关注整理 CLI 使用不同授权入口。已有授权有效时直接沿用，不需要为了整理目录或查看本地记录重新登录。

## 下载器

通过 `启动.bat` 打开窗口时保持空闲；首次开始任务或在设置页点击「校验账号状态」时才校验已有授权。

需要替换 Refresh Token 时，点击设置页「更新授权…」，通过遮盖输入的弹窗填写；取消不保存。保存授权和联网校验是独立操作。活动批次先暂停、等待收尾，再切换授权。详见 [设置和账号](../使用说明.md#设置和账号)。

`pixiv_config.json` 和 `www.pixiv.net_cookies.txt` 保存在项目根目录，属于敏感资料。Cookie 文件使用 Netscape 格式，不把浏览器 Cookie Header 随意粘贴到终端或配置。旧认证辅助代码 `pixiv_get_token.py`、`utils/pixiv_auth.py` 保留；重新获取授权需单独核查其适用流程，本次目录整理没有验证新的登录流程。

认证失败时区分授权过期、网站验证、限流和网络问题，依据实际提示处理。原图 403 不足以证明 Cookie 失效，避免靠反复开始任务测试授权。

## 关注整理 CLI

`organize.cmd` 复用普通 Chrome 中已登录的 Pixiv 页面。Cookie 和 CSRF 信息留在浏览器，不需导出，也不使用下载器 Token 作为网页分组授权。

```powershell
.\organize.cmd status
.\organize.cmd browser
```

上述命令不会向 Pixiv 发请求。首次 `connect` 才执行网页账号核对与绑定，后续网络命令也会校对当前账号。窗口要求、预算和恢复规则见 [CLI 说明](../ORGANIZER_CLI.md#启动与账号)。

下载器和整理网络作业分开运行。账号变化、登录失效、验证或限流时停止；先检查已保存进度，不重复提交待确认的账号改动。

## 资料保护

Token、Cookie、配置、下载账本和 `organizer_data/` 都不进入公开发布包。截图、日志和报错也不能包含凭据。恢复时保留当前新增成果，不为排查登录问题删除业务目录。

当前使用无需新增环境或依赖。确需安装或更新认证工具时，先按工作区 [安装守则](../../给AI的安装守则.md) 核查，不把历史安装命令当作默认启动步骤。
