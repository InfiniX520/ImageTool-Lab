## 保存什么

源码、离线测试、启动脚本、无凭据默认模板、设计/审计/进度文档、界面参考资料进入 Git。当前 A1 的小型审计证据另存[证据副本](audits/2026-11-12-a1/evidence/README.md)，便于从远端取回后核对。

图库、下载数据库/断点、授权文件、个人偏好、输出目录映射、关注整理资料、本机解释器指针、归档包及 .runtime 不上传。原来已跟踪的 config/config.yaml 和准备下载.txt 停止跟踪，电脑上的文件保留。config/default_config.yaml 是无凭据模板，继续保留。

项目仍使用现有 Python 环境。源码快照不包括解释器、已安装依赖或业务数据库；不能据源码标签宣称拥有完整数据备份。文档中指向工作区上级 .runtime、docs/maintenance、references 的历史路径依赖原工作区，不会随单项目克隆自动出现；本次未批量改写历史证据链接。

1. 开工先查看 git status 与当前进度，确认已有修改属于谁；不覆盖其他工作。

## 如何找回这一版

先查看版本，不改变文件：

```text
git show --stat checkpoint-2026-11-12-a1-audit
git log --oneline --decorate -10
```

需要查看或验证旧源码时，在不存在的新目录创建独立 worktree；下面从 JpgPng 项目目录执行：

```text
git worktree add --detach ../JpgPng_recovery_20261112 checkpoint-2026-11-12-a1-audit
```

这不会覆盖当前源码或图库。恢复目录仅供查看/对照，先阅读配置与数据库边界，不让旧代码直接打开较新版本的生产库。如果该目录已存在，换一个新目录名，不删除它强行重建。确认所需版本后再逐项恢复或合并；不使用 reset --hard/clean 清空当前现场。

另有本机 Git bundle 和改前源码 ZIP，位置见本批工作区维护回执；它们用于远端不可用时恢复版本历史，仍不包含被排除的业务数据。
