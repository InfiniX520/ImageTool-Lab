# 下一批开发指导：闭合 A1 边界

日期：2026-11-12。先读[总览](README.md)和[问题明细](FINDINGS.md)，再按本页 F0–F5 串行推进。[上一轮 R0–R6 指导](../2026-11-12-a1/DEVELOPMENT_GUIDE.md)继续承载总体架构和保护规则；本页只写本轮缺口，不重开总重构。

**验收目标**：计划的普通读取、仓库读取、幂等重放与显式维护审计遵守同一协议；真实枚举/观察能解释资产与内容换代；规模和取消约束覆盖实际 I/O。做到这些再评审生产接线。通过 1310 项现有测试不是这批工作完成的替代证据。

## F0：先确定本轮真实起点

1. 读工作区/项目规则、联合总表、TASK_PLAN、当前 Git 状态和这份指导。确认保存的标签与工作树关系。前序修复是在 main 上未提交的改动，不可 reset/clean 或用旧标签覆盖它。
2. 建立独立工作分支和新 runtime 批次；保存改前源码摘要、测试/文档基线、文件所有权和目标问题 ID。发现其他模型正在写同一个模块时先停止交叉修改，不能把两份未验收中间态当稳定基础。
3. 本次审计源码未改，174 个 Python 摘要见本轮 baseline；后续若有变化，以实际差异重新核对。历史报告不可覆盖；调查脚本均独占创建目录，不能在原目录直接重跑。
4. 将本轮反例改为明确期望的回归测试。probe_results 中 executed/completed 只表示调查跑到了结果，不能直接用“脚本退出 0”当修复通过。原两个性能探针因适配器错误未执行，正确版本在 performance_probes.py；NULL sealed 成员假设已被 DDL 拒绝，不要为此改代码。
5. 当前产品测试基线为相关 345 通过/3 跳过、全量 1310 通过/3 跳过。先读现有 XML，无需无改动地再重复完整测试。

使用现有解释器和 PYTHONNOUSERSITE=1，不安装依赖，不访问业务库/图库，不联网测试账号，不改 UI。需要修改符号前执行 GitNexus impact，并按当前源码补调用边；旧图索引未包含许多新符号，查不到不表示没有影响。尤其 _enqueue、PathRef 都涉及共享边界，不为本轮修复顺手重构它们。

## F1：先修计划引用闭包与凭据读取（AR2-01/02）

允许主要修改：archive_plan_store、必要的 archive_schema 维护审计入口、对应测试。优先用现有模块和接口，避免 schema→plan_store→schema 顶层循环导入。

### 第一步：列出同一计划需要成立的最小不变量

- 当前计划协议版本要求 scope_receipt 非空、合法、消费完整、与本计划条目和根绑定；不能只在 prepare 检查。
- 每个计划资产引用的 archive_contents 必须存在，且 content_key/asset_id/revision/size/sha256 完全一致；NULL 与非 NULL 是冲突，不是通配。
- 每条资产路径和来源标签有准确解释；download_receipt 要求实际 artifact 支持该内容，不能凭标签放过。
- 旧计划引用旧内容，不要求它仍是当前路径绑定；当前路径关联用于当前选择/更新，不能因文件换代让旧归档历史失效。
- 包索引、清单、容量、范围凭据按同一计划版本核对。哪些事实由 SQL 约束保证、哪些由定向检查保证，列清楚。

将这些不变量放入少量共用校验函数，由 load、replay、save-readback 调用。定向读取本批资产和关联内容，避免 N 个条目各跑一整套全库验证。全库审计可以调用同一协议检查枚举各批，但要有显式预算/取消与错误位置。

### 第二步：补三个入口矩阵

每个篡改场景分别经过 standalone load、ArchiveLibraryRepository.load、相同计划 replay；应一致拒绝并保留原数据。至少覆盖凭据 null/缺字段/未知版本/不完整/根不符、内容摘要 NULL/不同/大小不符/关联缺失、资产来源与 artifact 冲突。

完整旧代次计划仍应成功重载。用“无关历史内容损坏”证明日常操作检查的是正确引用闭包，显式全库审计能额外报告无关损坏；不要要求每次操作都拒绝全库任意错误，从而把优化全部撤回。

### 第三步：明确历史兼容规则

当前 version 2 下无凭据记录属于不符合当前协议，拒绝即可。若选择支持旧实验计划，给独立版本/非完整状态及明确恢复操作；不能用 `if receipt is not None` 作为隐式兼容。没有生产归档库需要现在在线升级，不做自动发现或修复生产数据库。

F1 退出条件：AR2-01/02 的原始反例转为明确拒绝；合法多代次历史仍可读；正常保存/重放/关闭重开通过；没有恢复每次全库扫描。

## F2：把资源边界落实到读取端（AR2-05）

不要先 fetchall 再检查预算。建议顺序：

1. 小型计划头严格解析并校验协议、整数类型、最大文档字节/段数/条目数。bool 不能当合法数量；负数、过大数、未知字段直接拒绝。
2. 按 batch 和序号迭代读取段。执行累计段数/实际 UTF-8 字节检查，发现超过文档预算立即停止；不能只信头里声明的长度。每段上限也要核对。
3. 一边读取一边累积摘要和预算。通过后再做必要拼接/解析，给峰值内存测量；若采用流式方案，保持协议简单，不引入新依赖或自制复杂格式。
4. 清单与头/容量/凭据使用共同严格 JSON 规则：拒绝重复键、NaN/Infinity、未知字段、类型错配、超界和缺失。不要只把 json.loads 换个名字而仍保留旧旁路。
5. 全库计划审计复用同一边界，不得因“维护工具”无限读入损坏段。错误要指出 batch 和哪个边界，无敏感路径内容。

验收至少包括：8 MiB 之下与之上、单段过大、很多小段累计过大、头谎报长度/段数、序号漏段/重复、重复 JSON 键、恶意大整数、普通 Unicode 分段、空/最大允许清单。边界测试以计数/受控适配器证明拒绝发生在未读完时，不用真实分配几十 GiB。

本轮 9 MiB 空白反例只是小型压力样本；不能把上限扩大到 10 MiB 来解决它。准备端与读取端同一预算契约，明确容量不足计划可保存用于展示，但它必须仍保留“不允许执行”的状态。

F2 退出条件：超界/重复键反例拒绝，2,000 文件合法计划完整保存和重载，故障后事务/连接状态可复用。

## F3：完成候选→观察→内容代次交接（AR2-03/04/07）

这步先写一页接口和状态表，再改代码，避免继续给 ScopeReceipt 添布尔值却不连接实际流程。不要同时大改生产 target_key。

### 明确四种身份

| 身份 | 作用 | 不能替代什么 |
| --- | --- | --- |
| 原始相对路径/根映射版本 | 找到用户选择位置、恢复原拼写 | 不证明这个位置仍是原文件 |
| device/file_index + size/mtime | 绑定当次候选与实际读取对象 | 不保证跨时间永不复用，也不是图片来源收据 |
| asset_id/revision/size/hash | 不可变内容代次，供历史包引用 | 不等于当前路径始终属于这个内容 |
| snapshot/run/check/解析记录 | 证明范围消费、观察与版本解析的交接 | 不自动证明历史 Pixiv 原图或网盘持有 |

### 实现顺序

1. 范围候选凭据至少绑定原始路径、根版本和物理事实。source 验证显式比较 physical_identity，不能依赖 compare=False 的数据类相等性；选择 digest 的字段也要相应升级版本。
2. 观察器输出已有物理身份/mtime/摘要。新增或复用一个小型交接结构，证明其读取对象匹配候选；读取前后被替换或变更的文件进入冲突/重新观察，不把新内容静默套旧快照。
3. 集中解析既有资产/代次：同路径同物理对象同摘要复用；同逻辑对象内容变更生成新代次；同路径换了物理对象需要明确替换策略/意图。未知历史摘要建立“当前观察基线”，不要修改旧未知代次来伪造历史证明。
4. 在唯一写入事务内按预期旧绑定执行条件更新。解析器在队外读到的旧值可能过时，队内必须再次检查。条件失败返回可操作冲突，不能自动重试覆盖新结果。
5. 新旧路径历史可并存，旧封包/回读继续指旧代次。现有“同路径永久只属于一个 asset”的应用检查与触发器必须与决定的模型一致；修改 DDL 要有临时副本版本迁移/拒绝方案，不直接删触发器过测。
6. 真实工作流有集中入口再接 receipt/plan，不要求调用者手工 replace ContentVersion 拼字段。保留纯单元 API，但不能把任意同路径同大小条目当作受信任观察。

如果本期不自动接受同名文件替换，允许保守返回“待确认替换”，但必须有明确下一动作，不能返回通用数据库异常后把范围说成收全。保存失败回滚是正确保护，不应为了顺畅关掉它。

### 路径别名决定

选择一个明确的根 ID 注册/规范化规则，在 ScopeRequest、PathRef、LocalObserver、receipt、仓库等入口一致执行。路径排序键与身份键分开，保留用户原始 Unicode 拼写。真实 Windows 目录项/物理身份可以证明某些别名；无法确定时返回冲突，不凭字符串猜两个文件相同。

必须保留 NFC/NFD 不同文件、真实硬链接的所有恢复路径。画/A 与画/a 的大小写别名、根 ID 大小写、ASCII 和非 ASCII 同一目录应有成对测试。不要把“整路径出现一个汉字就停止处理所有 ASCII 大小写”当最终规则。若确需改通用 PathRef，单列影响分析和下载主线回归；优先限定在归档身份解析边界。

F3 退出条件：真实文件首次入库、重复入库、原地等长改写、大小变化、os.replace 同名替换、别名重选、根映射换代均有预期结果；所有旧计划仍读回原字节事实。观察结果与内容基线可持久化/重开解释，不只在内存手工改字段。

## F4：修实际目录成本和页内中止（AR2-06）

允许主要修改 archive_scope 和对应测试。先运行本轮已保存计数，理解不是身份 dict 又退化，而是新增的真实拼写查询和每页 guard 引入另一条二次路径。

1. 显式选择按父目录分组，用一次有界 scandir 得到名称索引，附目录身份/状态。用于判断实际拼写和大小写别名；期间目录变化应使缓存失效或报错，不跨无关快照无限复用。
2. 给分页稳定性检查明确的总成本。可采用“枚举一次→有界消费→封闭验证凭据”的会话，或有依据的增量复核；需要在最终凭据完成前完成必要稳定性检查。不能每页重扫全部目录，也不能只信 mtime 后宣布没有目录替换。
3. 每个目录/祖先检查与扫描内部，以及结果返回前，检查取消和工作预算。预算定义为实际工作时间/累计 I/O，不混入用户空闲等待；一个阻塞 OS 调用无法即时打断的限制明确保留，调用之间必须响应。
4. 将用于“证明 O(n)”的测试改成测实际 scandir 调用/返回项、lstat、页数和取消点。保留身份比较计数，但它只证明一个子步骤。
5. 对页大小 1/100/1000、平铺文件/一文件一目录、重复选择/硬链接/深层目录分别测增长。测 n 与 2n 的实际操作数量，不用固定 wall time 断言受机器负载影响。

不要为了性能跳过完整摘要、取消目录安全检查、静默缩小范围或增加预览缓存。先修确定的重复 I/O，再测内存；8 MiB 声明字节只约束序列化/排队，不是 8 MiB 堆或 RSS 保证。

F4 退出条件：显式选择目录项访问随实际输入/目录规模增长合理；分页不再重复全树代价；页内取消/超限明确中止；根替换、目录成员变化和无关父目录活动的原回归保持。

## F5：独立整链、门槛与收尾

每个 F 包修改后先跑相关测试。F1–F4 稳定后跑一次全量，并将报告与最终源码摘要绑定。不要在最后一次功能变更后沿用前一份 green XML。

至少保留：

| 测试组 | 必须验证 |
| --- | --- |
| 计划损坏矩阵 | 所有 load/replay/audit 入口一致、关联闭包完整、无隐式 null 兼容 |
| 范围交接 | 同路径同大小不同物理对象被识别，真实观察必须对应候选 |
| 内容生命周期 | 变更/替换有解释，旧计划保留，冲突不覆盖 |
| 资源/解析 | 超限在有界阶段拒绝，严格 JSON 一致，异常后可继续使用连接 |
| 实际 I/O | 平铺/多目录/硬链接/小页计数及中途取消，无性能假绿 |
| 整链 2,000 文件 | 真实合成范围→实际摘要→代次解析→保存→关闭重开，逐项路径/摘要/凭据核对 |
| 故障与版本 | 单 writer、并发重放、进程锁、提交前异常、实验 schema 不匹配拒绝；生产接线前另补进程崩溃/WAL 演练 |
| 原下载主线 | 原图/多页、暂停恢复、名单、正常入口不因共享契约变动退化 |

本轮 2,000 文件正向实验包含真实观察与 writer，但没有落库 baseline→内容代次的解析记录；不要把这个实验称为 F3 已完成。它也不是深解码、来源真实性、500 GB 性能、封包或云端恢复测试。

测试使用现有解释器、`-s -B -X utf8`、关闭 pytest 插件自动加载和缓存、每次新 basetemp 与 XML。启动目录统一 JpgPng，**所有新测试/报告都写工作区上级 `../.runtime/<新批次>/`**；报告写项目内 .runtime 而计划指向上级，是上一轮的真实定位错误，不能再复制。

收尾用一份 current/validation 给出：问题 ID→实际改动→测试 XML→最终源码摘要→仍缺门槛→下一步；同时核对联合总表、归档日志和 TASK_PLAN 是否一致。错误和旧基线保留。旧 92/94、10k、内存比例的矛盾在当前说明纠正，完成的旧报告不覆盖。

Git 保存遵循[版本说明](../../VERSION_CONTROL.md)：新分支分阶段提交，推送现有私有仓库，保留旧标签，不强推。报告或源码尚未全部通过时明确标 WIP/待修；保存版本不是发布产品。F1–F5 后重新独立审查再进入生产接线；A2 密码/工具、A3 封包恢复、A4 夸克往返、A5 释放各自验收，不提前开放删除。
