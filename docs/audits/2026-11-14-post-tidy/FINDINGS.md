# 发现、复核与证据边界

基线 `4ba891e`。优先级按误判影响评估，不把“理论上可能”当已发生事故。下列动态验证只使用合成文件和 SQLite；本轮没有观察到真实图库丢失或真实库损坏。

## PA-01 / P1：备份核验可拼接不同版本的成功证据

位置：`core/library_maintenance.py:1145` 的 `verify_backup`；成员哈希在 1192 行，独立逻辑指纹读取在 1233 行，独立健康读取在 1267 行。行号对应冻结树；三个观察之间没有共同文件组身份/代次契约。

当前路径依次检查 sealed 字节、重新打开库计算 logical、再次打开库做 health/compatible。它们各自成功就合并 `ok=True`，没有证明来自同一稳定文件组。

两个独立反例：

1. 正常生成备份。在逻辑指纹完成后、健康检查开始前，通过另一个 SQLite 连接修改一行。第一次 `verify` 四项通过；立即再核验失败。证明修改发生在本次核验内部，不是仅讨论返回之后的外界变化。
2. 更严格的反例：构造结构合法、但 sealed 字节来自 A、logical 指纹来自 B 的清单。A、B 都是真实生成的健康数据库，差一行。核验前 A 失败；在哈希之后、逻辑读取之前把 A 改成 B，核验竟通过；对最终 B 再核验又失败。**不存在一个同时满足所有证明的版本**，因此不能用“结果对应较早时刻”解释这个通过。

证据：`test_pa01_verify_must_detect_write_between_proof_stages`、`test_pa01_no_generation_satisfies_all_proofs` 均失败；打印 `PA01_NO_COMMON_GENERATION True ok ok`。第二例明确使用不一致清单，这是为了测试验证器是否真正验证共同事实，不是宣称正常备份必定生成这种清单。

影响：`verify` 作为恢复和将来释放本地文件的门槛时，可能把互不相容的事实当作可信备份。正常、不变的备份对照通过；不能据此说所有现有备份都坏了。清单无签名、可被同时恶意改写的已知限制，与本项跨观察竞态不同。

下一步必须定义稳定版本的取得与失效协议，不能只在最后补一次 `exists()`、mtime 比较或把阶段顺序互换。详见开发指导 S1。

## PA-02 / P2：指纹排除条件误伤合法用户表

位置：`core/library_maintenance.py:897` 的 `_object_rows`，SQL 为 `WHERE name NOT LIKE 'sqlite_%'`。`_normalized_objects` 约 222 行也有相同条件，必须统一检查。

`LIKE` 中 `_` 是单字符通配符，而非字面下划线。SQLite 保留的是 `sqlite_` 名称前缀，合法表 `sqliteXuser` 不是系统表，却被上述查询排除。

反例创建两份兼容库，各有合法用户表 `sqliteXuser`，DDL 和行数相同，值分别为 before/after。`logical_fingerprint` 不含该表，两份 digest 相同，`compare_library.ok=True`；期望内容不同的测试失败。

影响限定：当前核心业务表没有这个名称，不能把它描述为现有 jobs/artifacts 都未被核验。但接口宣称覆盖所有非内部对象，inspect 又允许额外对象，扩展表/未来迁移一旦使用合法相近名称就会被漏掉。

修复应集中定义精确内部名称判定，遍历表、视图、触发器及索引时一致复用；保留标识符引用，不做全局字符串替换。现有指纹版本需定义兼容处理：旧清单若本来包含未覆盖表，修后应 mismatch/重生成备份，不能回退旧漏检算法来求绿。

## PA-03 / P2：归档身份关系的历史证明无效

位置：工作区 `.runtime/workspace_tidy_20261114_01/resume_archive.py:90,111`。枚举使用 `os.DirEntry.stat(follow_symlinks=False)`，直接把 `st_ino` 和 `st_nlink` 写入清单。

本机 Python 3.12.14 的实测：同一普通文件，DirEntry 返回 `[0,0]`，独立 `Path.stat` 返回非零文件 ID 和链接数 1。18 个 before 清单的 600,447 个文件，两个身份字段全部为 0。即使 before/after 相等，也只是零等于零。

独立复核同时确认：

- 文件大小与 SHA-256 全部一致，没有缺失；工作树 HEAD/分支/dirty/注册一致。
- 当前这些文件都能用 Path.stat 得到非零 ID；其中 5,800 个条目的当前链接数大于 1。
- 当前链接存在不能证明与搬迁前关系相同。没有旧文件 ID 的历史空白不能补写成“已证明”。

处置：本轮追加更正记录、明确内容校验通过/身份关系未证明两个结论。保留旧清单、原始成功/失败记录、全部历史目录；不重新搬一次来伪造搬迁前基线，不重放归档脚本。后续采集器要显式支持 identity-unavailable，优先用打开后 fstat/可靠的独立 stat 校验身份，且仍拒绝重解析点；见指导 G1。
