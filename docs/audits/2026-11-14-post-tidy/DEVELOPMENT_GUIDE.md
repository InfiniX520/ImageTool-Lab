## 3. S1：备份、恢复与完整指纹（一个负责人串行）

独占 `core/library_maintenance.py`，覆盖 PA-01、PA-02、WR-04 和 WR-01 的恢复步骤生成器。不得同时让另一个 lane 修改该文件的 CLI dispatch。

### 3.1 先严格校验 manifest，再碰文件

沿用 v6 的字段/大小/类型限制；bool 不当 int，成员名称唯一、大小写别名拒绝、相对路径不能越界。`copy_name` 必须是实际封存的数据库主成员，online/file_group 按各自协议校验 WAL/SHM。marker 文件被 seal 不能替代主库 seal。

预期输入、OS 和 SQLite 故障进入明确错误协议，JSON/文本同一事实和退出码；禁止捕获所有异常后假成功。复制开始到最终原子 manifest 完成是同一个异常收尾范围；只清理已证明属于当前操作的临时文件，不删除陌生文件、不跟随链接。修复必须保留 primary failure 与 cleanup failure 两个事实。

### 3.2 共同版本协议先设计，再写代码

三个独立连接都“只读”并不构成一个共同版本。只给 logical/health 共用 SQLite 事务仍没有绑定 sealed 的文件字节；只拿 inode/mtime 也不能证明哈希过程中未变化。需要同时回答：

- 被核验主库、WAL、清单以及目录条目如何识别，打开后路径替换如何发现；
- 逻辑指纹和健康检查如何共享同一个数据库读快照；
- 原始 sealed 字节与该快照之间如何建立关系；
- file_group 中匹配的主库/WAL 是否成组取得，不能先复制主库、再复制变化后的 WAL；
- 外界改写、busy、预算或取消时如何失败，是否保留可诊断现场；
- 自有隔离副本只供核验，任何 SQLite 打开可能产生 sidecar 时不污染被核验原目录；不得对用户库执行 checkpoint、切换 journal mode 或 VACUUM。

可选择受控隔离副本加稳定性封存，或操作系统句柄/锁与 SQLite 快照结合，但必须先用反例证明所选实现有效。不要为了“修好 PA-01”直接给文件夹改只读属性、修改 ACL、杀进程或自动移动用户备份。返回后的任意外界修改不在一次核验保证内；报告必须写明证明作用域与时间。

必须通过的新增矩阵：正常 static 备份；hash 后改行；logical 后改行；同路径替换；等长改写；不一致 manifest 在阶段间切换（本次 A/B 反例）；WAL-only 提交；成员删/增；busy/取消/预算。对所有失败明确 `ok=False`，并断言用户源文件组未被验证器写入。

### 3.3 修正对象枚举

精确排除字面 `sqlite_` 前缀，不使用含未转义 `_` 的 LIKE。所有 schema 对象集合用同一个定义；验证大小写、`sqliteXuser`、`sqlite9user`、合法带引号名称、view/trigger/index，以及真实 SQLite 内部对象。

保留类型编码、稳定行序和全行内容哈希。需要明确：旧清单已经漏掉合法用户表时，正确行为是兼容性拒绝或 mismatch 并新生成备份，不能通过删除 extra table、降级旧算法或忽略新 digest 差异维持绿灯。不要修改现有业务 schema。

### 3.4 WR-01 的恢复演练

先修 runbook 和 `_restore_steps` 的危险顺序，再在合成副本演练：所有连接/辅助进程关闭、备份模式与成员正确、当前主库/WAL/SHM 整组保留到独立位置、准备并校验匹配恢复组、重开逻辑对照、失败可退回原组。只关闭任务不等于关闭进程；不要给出无条件覆盖主库然后删除 WAL 的操作卡。真实恢复继续另批。

## 4. S2：扫描全程与外部根

独占 `core/library_audit.py` 和建议的新聚合模块，不碰 S1 的维护入口文件。主线程在合流之后串行接 CLI。

- 复用 `OutputLocations.load` 的只读映射语义，但先检查其异常边界：文件不存在与文件存在却读不了要分开；原始 open 的 PermissionError/OSError 也要统一到 typed mapping error。合法外部根不猜测、不 mkdir；未知 root 不回退项目根。
- 默认全程扫描与显式 page 扫描分开。200 是页大小，不是全库总量；裸 after 只能是 continuation，末页全 match 不能覆盖之前错误，也不能冒称全库完成。
- 每页短读事务；全程文件/字节/时限预算及取消；聚合后只给一次最终结论。说明跨页遍历不是全库同一时刻快照。
- 201/401 行、首/中/末页 missing、外部根掉线、坏映射、重复/跳跃 cursor、预算与取消都要覆盖；必须验证命令行最终退出码，而不只是引擎字典。

## 5. S3：核验面板与恢复身份（主线程）

按 v6 处理 WR-05/06/07，不改变已认可的界面风格和无缩略图策略。至少：51 行可翻第二页；显示本页/总数；仅对当前页显式选中项操作；切换批次、刷新或退出时作废可见行/选择/按钮/cursor/未派发队列；加载失败明确显示错误。

`expected_delivery_id` 是用户所见目标，不是让前端控制后端的 `previous_delivery_id`。仓库先比较当前链接身份，不符就 `state_changed` 且 **零文件观察**；符合后继续既有 observation、intent、root/policy、generation 和 CAS。现有保护一项都不能删。
