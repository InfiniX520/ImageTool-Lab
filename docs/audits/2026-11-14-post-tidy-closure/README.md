## 5. 如何复现

在独立 checkout 执行，不在日常工作树中注入故障。使用现有 Python 与 pytest，不安装环境。

```powershell
$py = 'D:\Miniconda3\envs\JuiLiu\python.exe'
$env:PYTHONNOUSERSITE = '1'
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:TCL_LIBRARY = 'D:\Miniconda3\envs\JuiLiu\Library\lib\tcl8.6'
$env:TK_LIBRARY = 'D:\Miniconda3\envs\JuiLiu\Library\lib\tk8.6'
& $py -s -B -X utf8 -m pytest docs/audits/2026-11-14-post-tidy-closure/evidence/test_closure_audit.py -q -s -p no:cacheprovider
```

仅此命令在公开 checkout 中会显式跳过 PA-03，因为归档采集器不在仓库。要复现本机完整 14 项，先将 `PIXIVKEEP_ARCHIVE_COLLECTOR` 指向本批 `archive_tool_snapshot/resume_archive.py`，并核对 [results.json](evidence/results.json) 的源摘要。本审计已用该冻结快照跑完，未跳过。测试中的 junction 两端都位于 pytest 自己的临时目录，断言仅检查合成哨兵文件。

完整套件按上表三组运行；每次指定新的、尚不存在的报告和 basetemp 目录，不能复用并覆盖证据。红测试不加入普通 `tests/` 默认集合，不添加 xfail，不削弱断言来让报告变绿；下一轮修复后再作为回归接入。
