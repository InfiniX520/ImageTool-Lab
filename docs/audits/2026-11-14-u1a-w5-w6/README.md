## 已确认的进展与保留边界

- RFB 观察缓存的正向结果在跨调用复用前重新观察；不能靠旧 size/mtime 判定严格一致。回执重放仍单独幂等。
- 进度无法持久化/容量截断时避免同一前缀无限重试，剩余页预算传入单文件观察；对应原始反例通过。
- cleanup 的 EOF 与预算停止分开；账本错误向外传播；中间 handover 可达较早 completed，四条语句预算内的相应用例通过。
- 新列表/恢复端口走后台所有者线程；scan 不授权补下载；默认在线备份保留为正确方向。
- 备份恢复文件组的“残留 WAL”怀疑在本轮合成场景未复现：实际清单含空 WAL/SHM，整组覆盖后读到正确旧快照。将其保留为通过对照，不列成缺陷。
- 本轮没有复测真实外置卷/真实重解析点、进程硬崩溃断电、夸克往返、500 GB 库规模性能。现有预算不等于单次操作必定在时限内结束；网络卷系统调用、长事务与事件扫描成本仍需另立实测。
- 旧的 finish_source 超时后最终结果协议、意图投影/索引、carry 长事务、claim SQL 数量、旧 record_manager 健康门、归档封包/回读/释放仍为既有待办，不因 W5/W6 交付而关闭。
