## 对实施方两处裁量的答复

**MISSING 120 秒负面窗口可以作为受限的调度优化保留。** 它不能成为健康/完成证据。本审计新增“缓存缺失后文件已恢复”对照：真实 executor 在首个 GET 前以 `output_file_conflict` 暂停，0 请求、恢复的字节保留。若在下载期间恢复，仍必须保留发布冲突检查。代价是暂时多一个 repair/hold，界面后续需要明确重核验入口；不能把负面缓存说成文件仍然缺失的实时证明。

**补偿失败后不再进行第二轮盲写，可以接受；吞掉账本读取故障不可以。** 可读账本中的 CAS 竞争与 unreadable ledger 必须是不同结果。本轮 RFB-05 分别覆盖私有分类器和公开 recover_local。

**正面缓存的等长原地修改不能作为质量妥协接受。** trusted 复用根本不经过 PageDeliveryExecutor 的发布/确认门，“后面还会校验”的解释不成立。它也不是文档已登记的预检→writer 毫秒级竞态，而是最长 900 秒、可跨 resume 的独立缺口。
