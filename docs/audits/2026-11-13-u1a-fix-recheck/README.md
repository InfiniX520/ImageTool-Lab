## 不应误报的边界

本轮最初假设“直到最终 link 前，排除均应获胜”。核对契约后发现，当前协议选择的是 `publish_authorized` 的读取判定点：读取允许后才写入 EXCLUDED，本次仍可能完成。最终测试将其改为**通过的行为刻画**，没有计入缺陷；早期失败日志保留。若产品需要“排除按钮返回后，尚未落盘的页一定停止”，必须另设计发布预留/排除仲裁与崩溃语义，不能把再加一次只读查询当作原子保证。

另一个通过项验证完好文件恢复与历史收据保全。没有证据表明这轮修改破坏原图字节、引入转码或改动旧归档 schema；未修改的 A1/AR4 结论保持其原范围，不凭本次通过扩大为真实云端验收。
