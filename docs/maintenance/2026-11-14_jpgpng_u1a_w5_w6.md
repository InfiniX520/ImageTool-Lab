## 4. 边界与未做（明确记录，不算缺陷）

- 不改真实库、不迁移 schema、不切日常入口：切换由用户一条命令决定（runbook §4）。
- 不做"授权补下载"批量入口；`suspended`（批次停住）不当事故；`missing` 只表示"本次观察不在"，不授权修复。
- 不做 quick_match 快速核验；仍只用完整 SHA-256；不做跨会话观察缓存。
- 每页字节上限仍是模块常量（8 GiB），`config/collection_v2.json` 不新增字段（旧版本读取会因 `settings_unknown_fields` 拒绝，需 settings v2 迁移）。
- 界面面板不分页：只列前 50 行并提示"还有更多未列出"；全量巡检走 `maintain.py scan`。
- `suspended`/`pending`/`retry_wait` 只展示不提供动作；`recoverable` 额外要求批次 `running`（否则 `blocked_reason=batch_not_running`），因为恢复入口对非 running 批次直接拒。
- 真实外置卷掉线仍只用"把目录改名"模拟，没有真实外置盘/网络盘演练。

## 5. 与冻结稿的偏离（登记）

| 项 | 冻结稿 | 实现 | 理由 |
| --- | --- | --- | --- |
| 备份方式 | 复制 main+wal+shm 一组 | 默认 `online_backup`（SQLite 在线快照，单文件且 journal 归一为 delete），`file_group` 保留为第二模式 | 备份几乎总在应用开着时执行；文件组复制会得到撕裂副本。实测：源连接只读时 `conn.backup()` 在另一连接持未提交事务时仍产出一致快照 |
| `verify_library_copy.ok` | 未定义 | `ok` = "忠实副本"（对象/计数/完整性一致）；是否兼容单列 `declared_ok` | 两个问题不同：副本可以忠实但版本不接受，反之不可 |
| `inspect` 额外字段 | — | `journal_mode`、`warnings`、`healthy` | 供人读与 CLI 退出码使用 |
| 空库判定 | — | 合法 sqlite 但无表 → `empty` | 与 `_inspect_existing` 视为新库一致 |
| 额外对象 | — | 报告但不阻塞（`extra_objects` warning） | 打开路径只校验自己的声明，兼容性必须等于代码实际行为 |
| 列表行字段 | 12 个 | + `attempts`/`retry_at`/`batch_phase`/`blocked_reason` | 界面要解释"为什么停住"和"什么时候再试" |
| `states` 空序列 | — | 抛 `LibraryError` | 空集合是调用方 bug，不是"不过滤" |
| 巡检 `stats` | 11 键 | + `excluded` | excluded 是合法 verdict，不计数会从汇总里消失 |
| 巡检预算 | files/bytes/seconds | + `per_file_seconds`（默认 60） | 单文件不能吃掉整轮预算（同 RFB-06 教训） |
| 巡检游标 | — | 指向"最后一条有结论的行" | 被预算停住的那一行下一轮要重查，不能跳过 |
| 巡检 `truncated` | 预算耗尽 | 分页或预算任一 | 两种都是"这不是全库" |
| 巡检 `changed` 行摘要 | — | 带 `observed_sha256` | 等长改写时它就是证据；`ArtifactHealth` 的限制只针对 missing/unreadable/root_unavailable/changed_during_check/unknown |
| 巡检 limit 越界 | — | 抛 `ContractError`（不 clamp） | 与 `list_cleanup_candidates` 的静默 clamp 不同，但审计确认无实害；已在 CLI 转成 exit 4 |
| 界面 view 方法 | 3 个 | + `set_verification_busy` | 派发期间必须能禁用按钮并显示进度 |
| 界面 action 名 | `verification.list` | `verification_refresh` / `verification_recover` / `verification_batch` | 仓库既有 action 全是 snake_case |
| 面板挂载 | `collection_app.py` | 由 `collection_view` 自建 | 少改一个文件，demo 模式自动可见 |
