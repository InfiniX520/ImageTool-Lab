# 03 来源、关注与可选筛选

版本：v2，2026-10-21。来源协议见 [01](01_ARCHITECTURE_AND_CONTRACTS.md)，持久化位置见 [04](04_RECORDS_AND_MIGRATION.md)。P4 已完成离线核心，实际适配边界见第 10 节，不代替 P8 真实小样。

## 1. 功能保留与统一入口

| 来源 | 用户意图 | 必需输入 | 完成范围 |
| --- | --- | --- | --- |
| 关注历史（默认） | 逐步补齐关注画师作品 | 账户、保存方案、可选筛选 | 本轮关注快照和各画师可访问历史 |
| 关注新作 | 收集关注更新 | 账户、保存方案 | 接口可返回的新作窗口，不能替代完整历史 |
| 指定画师 | 收集一位或若干画师 | 画师 ID 列表 | 各画师当前可访问作品 |
| 搜索 | 按关键词查找 | 关键词、匹配/排序、可选日期 | 已查询页及接口可达范围 |
| 排行榜 | 下载某类榜单/日期范围 | 榜单类型、日期范围、采样方式 | 实际返回的榜单日期与覆盖页 |
| 相似推荐 | 从作品找相似作品 | 起始作品 ID | 推荐接口返回范围 |
| 个性化推荐 | 接收账户推荐 | 账户 | 当前推荐结果窗口 |
| 多来源交集 | 同时满足多个来源集合 | 各来源独立参数 | 各来源已查询集合的交集 |

所有入口最后使用相同的属性筛选、去重、页级交付和名单协议。参数不适用时明确禁用并解释，不能悄悄忽略；切换来源只改变草稿，不修改运行中的任务。只有结构合法且无错误字段的空作品列表才算空结果；缺失预期字段、解析失败或错误对象不能当成空画师/空榜。

## 2. 关注历史：开始与恢复

### 2.1 一次批次的顺序

1. 本地验证草稿，确认账户引用、任务条件版本、输出根和原图/多页要求。
2. 若存在相同语义的未完成任务，默认提供“继续历史补全”；恢复待办受本批预算约束，不能无上限抢占新任务。
3. 恢复未完成的关注快照获取；首次或用户同步关注列表时获取当前快照。完整快照可增量更新画师集合，已知快照可以在首页显示更新时间。
4. 按选定顺序处理画师：重放必要分页、评估候选、保存页待办和候选结果，再确认画师游标。
5. 来源预算结束则停止查找，已接收的有限队列排空后保存本批结果；用户暂停则尽快停止传输，保留片段和待办。
6. 记录遍历覆盖与交付结果，显示下一位/当前画师位置、未决项和本批名单。没有未决项并且范围确实耗尽，才能表示当前范围已处理完。

完整遍历与后续更新是不同轮次。历史完成后，下一次“继续补全”可使用已有增量扫新能力检查已完成画师，并补入新关注画师；界面说明它是一次新的更新检查，不把旧的完成状态当永久无新作。

### 2.2 关注列表变化

| 场景 | 行为 |
| --- | --- |
| 新关注画师 | 按稳定 artist_id 加入待补全，旧画师断点保持；默认追加，支持显式优先某位 |
| 取消关注 | 只有完整快照确认后才停止后续历史调度；已下载文件、记录和当时任务结果保留 |
| 重新关注 | 恢复该画师身份与历史进度；重新检查更新/未决范围，不从空记录开始 |
| 画师改名/关注顺序变化 | artist_id 不变，更新显示名称；序号只作为界面定位，不作为持久主键 |
| 快照分页失败/预算耗尽 | 保存快照分页进度，标为不完整；不根据缺失画师判定取消关注 |
| 已有可用快照，新同步尚未完成 | 可继续已知画师任务，显示“关注列表待同步”；不重复从第一页消耗每批预算 |
| 更换登录账户 | 不复用其他账户的关注游标；既有图片记录仍保留，账户关联与内容去重分开 |

本版不在打开首页时自动同步，也不每次切页刷新完整关注列表。同步由开始/继续流程中的明确策略或“同步关注列表”操作触发，进度和请求计入预算。

### 2.3 画师分页与防漏

- 持久化 artist_id、来源分页游标、页内位置、最后处理作品 ID、条件版本与候选确认信息。
- 同一页重放允许重复发现；唯一键阻止重复待办/记账。分页中断不能只保存“下一页”而跳过尚未持久化的当前页剩余作品。
- 分页内容变化或页内锚点消失时，回退重读当前及必要相邻页，靠作品 ID 去重；仍无法定位则标记覆盖待复核，不能按数组索引强行跳过。
- 接口结果在爬取期间可能变化，客户端游标不是服务器一致性快照。完成说明记录扫描时间和范围；周期性核验历史是显式操作，不对静态快照不存在的保证作承诺。
- 来源抓取完成后仍有页待办、未知筛选字段、失败或不支持类型时，画师显示相应未决数量，不显示“全部已下载”。

### 2.4 继续、从头与仅重试

| 操作 | 精确语义 |
| --- | --- |
| 继续 | 沿原任务条件和稳定身份恢复，创建新的 batch_id |
| 从头检查 | 新扫描轮次从头枚举，但继续利用已有完成记录；不删除记录、不全部重下 |
| 从指定序号/画师开始 | 从本轮快照定位，显示所跳过的前段范围；不能称覆盖了全部关注 |
| 仅重试未完整画师 | 只调度有失败/未完成工作的画师，区分查询失败和图片交付失败 |
| 仅重试失败页 | 只恢复页待办，不重新遍历所有画师 |
| 优先补这位 | 在安全暂停边界切换调度，当前页先保存恢复状态；不重置其他画师 |

## 3. 关注新作与增量边界

关注新作保留现有入口，并与历史补全使用同一过滤和交付管线。每次查询持久化分页进度、已见作品 ID 及停止锚点；作品 ID 不能未经验证就当作严格发布时间排序。

增量检查采用已确认的旧作品锚点与少量重叠查询，不能只读一页就更新“已检查到现在”。直到本轮锚点区间内候选全部完成持久化确认，才推进增量水位；遇预算、排序不稳定、锚点未找到或接口窗口截断，保留旧水位和待检查区间。

历史中的已完成画师增量扫新可以复用现有 `newest_illust_id` / `swept_at`，但现有每画师最多 10 页的扫新上限只表示本轮预算，达到上限不能宣称没有遗漏。长时间未运行后，提示使用历史补查覆盖新作接口可能不再返回的范围。

## 4. 筛选条件组合

### 4.1 生效规则

`min_bookmarks=null` 表示关闭；非负整数表示启用。`exclude_ai=false` 表示关闭；true 时仅接收能判断为非 AI 的作品。各启用条件默认逻辑 AND；来源集合交集另行定义，不把两种含义混成一个开关。

| 收藏条件 | AI 条件 | 行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 不因收藏/AI 属性过滤；只取下载必需元数据 |
| ≥1000 | 关闭 | 仅收藏达到阈值；缺收藏值不能当 0 |
| 关闭 | 排除 AI | 确认为 AI 则过滤；未知不能伪装成非 AI |
| ≥1000 | 排除 AI | 两个条件都满足才接收 |

条件依赖字段缺失时，允许一次受共享预算约束的元数据补齐；仍未知则记 `metadata_unknown` 并保留可重评估项。网络失败按统一重试处理，不为每个 UI 字段再请求一次。仅为下载名单展示而缺失的字段不发补查请求。

筛选结果保存实际观察值、观察时间、规则版本和原因。多项不满足可保留多个原因，但候选统计只计一次。已知明确不满足时可直接过滤，无需为了另一个未知字段继续请求。

### 4.2 条件变化与断点

任务的范围指纹包含账户、来源及范围、过滤规则、原图/多页、输出身份和命名版本；预算、日志等级、窗口外观不改变内容语义。旧指纹含绝对路径，必须通过迁移映射判断，不能直接替换散列。

| 变化 | 处理 |
| --- | --- |
| 只调整每批预算/并发 | 新批次使用新资源参数，任务范围和旧断点可续用 |
| 降低收藏门槛/关闭排除 AI | 创建关联旧任务的新条件版本，补查以前被过滤的范围；旧任务进度保留 |
| 提高收藏门槛/启用排除 AI | 已下载不删除；新版本只接收新条件允许的待办，运行中旧批次不被修改 |
| 首图改全页 | 补齐缺页；既有首图不因任务变更而重复下载 |
| 更改目录/命名/账户/来源范围 | 新语义任务；通过明确关联复用数据，不能错误沿用一个旧游标 |

v1 对规则变化采用正确性优先的重新枚举方案，利用页记录去重；若保存的候选信息足以覆盖某段，可离线重评估后补查剩余范围。不能为了避免查询，假定只缓存了下载成功作品就拥有所有被过滤作品。

收藏数会随时间变化。一次扫描的“不满足”只代表当时观察值；同条件以后需要重新核验低收藏旧作时，使用“重新检查历史条件”。默认增量只追新作，界面明确这项覆盖边界，避免每次续跑无意全量扫描。

## 5. 预算和计数

本批限制显示为“最多新增/补齐 N 个作品”，恢复待办也占本批处理名额。每个确需写至少一页的作品在事务内占一个名额，多页不增加作品名额；已有完整记录、条件过滤不占名额。名额在本批内不因最终失败反复释放重填，避免下载失败时不断扩大任务范围。

查询预算包括关注快照、来源分页、必需详情和实际重试请求；CDN 传输有独立并发、尝试和时间约束。两个预算都显示使用量，不把总页数当作请求次数。尽量在接收候选时补齐原图页元数据；已入队 URL 失效后的刷新同样计查询预算，预算耗尽则保留待恢复项，不冒充网络/权限失败或绕过预算。

| 计数 | 含义 |
| --- | --- |
| 查看次数 | 来源实际返回的出现次数，包含重复 |
| 不同候选作品 | 本批按 illust_id 去重后的候选 |
| 属性过滤 / 字段未知 / 不可访问 / 不支持 | 互斥的当前候选结论；不计下载成功 |
| 已有完整作品/页 | 本批通过既有记录去重的结果 |
| 已接收作品 | 已持久化并占名额的作品，可能尚未下载 |
| 本批新增图片页 | completed_batch_id 等于当前批次的交付事实 |
| 作品完成 | 本次请求所需页全部完整；与实际新增页数分别显示 |
| 最终失败/待核验页 | 本轮停止时仍未解决的结果；尝试失败不重复累加 |

预算耗尽是暂停原因，不是“下载了所有符合条件作品”。未知远端总量显示已处理数量，不制造分母和 100%。

## 6. 排行榜

日期输入使用 ISO 日期并提供就地校验。类型用中文名称，内部代码通过经过测试的映射；只显示验证支持的类型/日期组合。默认“最近已发布”，响应返回后记录实际日期；不能把本机今天强当榜单日期。

范围任务有一个跨日期去重后的作品名额池和独立查询预算。逐日快照与周/月代表快照须明确选择，默认按新到旧处理已选快照；实际支持的接口日期语义通过小样验证，不能用固定天数步进猜测月榜。

同一作品多日上榜只保存一次图片，但来源出现记录保留榜单、实际日期、名次。断点含日期序列位置和该日期分页；某日合法空榜不做指数退避，某日请求失败单独记录。默认认证/限流阻断批次，单日普通不可用保留未决项后可继续下一日，最终为部分完成。

跨日结果按日期展示原名次；“最佳排名”只能称本地汇总，不能称统一官方榜单。切换界面条件后，旧查询返回须按请求版本丢弃显示更新，但已提交任务仍保留自己的结果。

## 7. Premium 搜索与推荐

官方说明 Premium 包含按人气排序搜索；这不证明当前程序所用账户、App 接口、网页授权都已验证可用。[Pixiv 官方权益说明](https://www.pixiv.help/hc/en-us/articles/235583788-What-sorts-of-benefits-are-available-to-pixiv-Premium-members)

账户状态分别记录 App 授权、网页 Cookie 状态及查询能力验证时间；不显示凭据。能力值使用 supported / unsupported / unknown，网络失败归 unknown，不把临时故障当永久无会员。

请求记录 `requested_source/sort` 和响应确认的 `actual_source/sort`。热门不可用时，默认保留原请求并解释；若用户明确选择允许回退，则记录回退路径。不能因为少量热门样本未达到收藏门槛，就悄悄改为推荐/排行后仍显示“热门搜索”。

合法空结果立即结束当前查询；只有可重试故障才重试。分页与已查看范围可见，最高收藏低于阈值的首屏不能自动证明所有后页不满足。相似/个性化推荐同样保留来源身份，不作为未声明的搜索替代品。

## 8. 多来源交集

每个来源独立 QuerySpec、排序、分页游标和查找预算，统一按作品 ID 求交；属性筛选可在候选已具备字段时共享评估。来源出现写入有索引的本地暂存表，避免把无限结果集合驻留内存。

当作品在所有已选来源都确认出现时可以入队，不必等待所有来源穷尽；但只有每个来源覆盖状态已确认，才能描述交集范围。有限样本无交集显示“已查看范围内无交集”，不写“没有符合条件的作品”。

任一来源认证失败或明确限流停止相关任务；预算终止保留所有已取集合和游标。恢复后重复发现幂等，不再次下载已接收交集作品。首版只保留现有交集功能，不增加通用布尔查询语言。

## 9. 验收重点

新关注追加、取消/重新关注、不完整快照、列表改名/换序、页内插入/删除、换账户、扫新锚点未找到、预算在页中用尽、过滤未知与规则放宽、多页补齐、全任务排行限额、排序回退透明、有限交集无结果，均进入 [07 的行为矩阵](07_IMPLEMENTATION_AND_ACCEPTANCE.md)。

## 10. P4 实施落点

已实现的关注适配入口为 `FollowCollection`，调用者明确激活批次后在其拥有的来源线程运行；本对象不建线程、授权或图片预览。`PixivFollowSource` 包装已有 App 客户端，公共/非公开关注分开，画师作品显式使用 illust/manga/ugoira 分区，后者明示不支持；不依赖未核验的默认类型包含范围。

App 客户端必须禁用重定向/自动重试并提供最长 15 秒的连接/读取设置。每个方法至多调用一次 SDK；来源请求先记预算预留，本次实际客户端调用数另记。默认来源总时长上限 300 秒，批次配置更短时取更短值；请求、画师、作品预算独立生效，任一用尽都保存待续范围。增量锚点每次最多查 10 页，不把此上限当成完整历史范围；达到边界不更新为完整覆盖。原始响应在 SDK 解码前的大小限制仍归 P5，不能以规范化结果至多 2000 项冒充全链路有界。

范围指纹排除 request_id 和资源预算，保留账户、来源参数、过滤、原图/多页、输出和命名；关联请求可记录父任务。恢复页有全局收据与每批收据，既不重复发现/交付，也不丢当前批的已有页关联。名单查询/导出归 `LibraryQueries`，状态和当前证据见[进度](../REFACTOR_PROGRESS.md)；旧 GUI 和实际账户尚未接入。

## 2026-10-24 交付说明

关注默认历史补全，新作、指定画师和独立附加筛选已接入；其余来源为搜索、排行榜、画师、个性化/相似推荐和有限交集。日榜日期范围最多 31 天；交集每来源默认 200、上限 5000 个去重候选，预算/候选上限结束不称完整覆盖。已知不符合条件优先于未知；仅对需要的未知字段按预算查详情，仍未知则名单保留原因。持久游标和请求参数用于原任务恢复；来源表单草稿只保证当前窗口内切换保留。

真实相似推荐分页含 indexed viewed/seed 字段，末尾标记与 offset 不递增但 viewed 集合增加的形态已适配。校验同源/同端点、参数大小和进展，非法或无进展游标明确终止。会员热门排序及真实来源小样已有证据，不做静默降级。详见[进度与实测](../REFACTOR_PROGRESS.md)。
