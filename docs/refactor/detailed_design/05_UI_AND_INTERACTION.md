# 05 界面与交互

版本：v3，2026-10-22。用户已重新明确此前认可的两张截图是风格基准，布局可以按功能调整。以下是界面的功能规格；视觉以[用户确认的基准](../designs/approved_2026-10-21/VISUAL_BASELINE.md)为准，不再自行更换风格。基准不表示代码已实现或每个像素/模拟数据都须固定。

## 1. 设计目标与参考使用

常见操作是继续收集关注画师历史、调整可选筛选、查看结果。界面围绕这三件事安排，保留其他来源入口。任何页面不请求缩略图或画师头像，也不为名单解码本地原图。

参考研究见[总体规划第 4 节](../REFACTOR_PLAN_2026-10-20.md)。沿用 IWLTY 的细线、字体层次和少量蓝色；借鉴 21ST 的可移除筛选、可搜索选项和展开详情；结合已研究的 Linear 信息层级。参考其适合下载器的交互和视觉细节；允许适量阴影及专门的美化代码。依赖、绘制方式和框架按实际收益与开销选择，遵循基准中更新后的用户约束，不整体照搬参考项目的运行栈。

用户本轮提供的[关注页](../designs/approved_2026-10-21/follow_user.png)和[任务页](../designs/approved_2026-10-21/tasks_user.png)已经保全原件，并作为明确的风格依据。早期[关注草图](../designs/follow_first_2026-10-20/follow.png)和[任务草图](../designs/follow_first_2026-10-20/tasks.png)保留。正式界面先完成实际可交互的两页与实测，直接对照基准；设计图不能代替运行效果。前端由主代理亲自实现。

## 2. 页面与导航

固定导航：**关注下载 / 下载任务 / 其他来源 / 下载记录 / 设置**。导航使用文字入口与活动下划线；选中状态同时有文字/焦点说明，不仅靠颜色。任务切页后继续运行，详情通过内嵌区域展示。

| 页面 | 常用内容 | 低频内容 |
| --- | --- | --- |
| 关注下载 | 历史/新作选择、当前方案、继续/开始、结果摘要 | 指定起点、同步关注、从头检查、每批预算 |
| 下载任务 | 活动批次、等待任务、已结束批次、暂停/继续/结果 | 调度顺序、未决页详情、复制任务 |
| 其他来源 | 指定画师、搜索、排行、相似/个性化推荐 | 多来源交集及每来源覆盖 |
| 下载记录 | 本批结果与累计历史、搜索、页状态、打开目录/导出 | 文件核验、缺页修复、明确重下 |
| 设置 | 保存目录、命名、账户状态、网络、日志 | 迁移信息、记录维护、诊断导出 |

打开程序优先建立可操作界面，加载本地方案和简短摘要；账户网络验证和关注列表同步由开始/继续等明确操作触发。不能为了打开首页先扫描图片目录或读取整个日志。

## 3. 关注首页

宽窗口的逻辑布局如下，实际尺寸按 DPI 与可用工作区换算：

```text
应用名            关注下载  下载任务  其他来源  下载记录  设置
──────────────────────────────────────────────────────────
关注下载                                  账户状态 · 更新时间
历史补全（默认） | 关注新作

继续收集                          本次条件
当前画师与断点                     [ ] 最低收藏   数值输入
已完成 / 未完整 / 待处理            [ ] 排除 AI
本批预算与保存目录摘要               原图 · 全页 · 已有记录去重
[继续历史补全]  查看结果             更多下载设置

画师进度文字表：画师 | 遍历状态 | 页结果 | 最近处理
──────────────────────────────────────────────────────────
简短状态      日志（可展开）                   打开保存目录
```

无断点时主按钮为“开始历史补全”；有兼容断点时为“继续历史补全”。新作模式明确写“下载关注新作”。重试只针对未完整项，不把“从头”放在最醒目位置。

默认显示保存方案；不因历史模式自动勾选排除 AI 或覆盖收藏数。开始按钮附近用一行文字说明实际生效条件和预算。条件关闭时保留输入值但不生效；再次启用可沿用该值。

画师进度只展示元数据和状态；选中画师可“查看本次作品”“优先补这位”“打开目录”。累计全量画师表分页查询，不能一边刷新日志一边重绘全部列表。

### 3.1 首次与日常流程

| 场景 | 主要操作 | 反馈 |
| --- | --- | --- |
| 首次打开，已有合法设置 | 确认摘要 → 开始 | 开始时检查授权与目标目录，缺项就地指出 |
| 日常继续历史 | 继续历史补全 | 沿原条件恢复，新 batch_id；不用重新填表 |
| 新关注画师 | 同步关注列表或开始流程中的同步 → 补全 | 新画师数量、完整/未完整快照和加入位置可见 |
| 调整筛选后开始 | 修改条件 → 显示变化摘要 → 创建新条件任务 | 说明需要补查范围，旧进度保留；不是每次都弹确认框 |
| 要下载新作 | 选择关注新作 → 开始 | 历史任务仍保留，其他活动批次存在则排队 |
| 查看刚下了什么 | 本批结束后点击“查看本批名单” | 直接定位本批；不要求从日志复制作品 ID |

“打开页面”“切模式”“输入画师 ID”均不自动启动请求。仅对确实有破坏性的清空记录/覆盖操作保留明确范围与备份流程，普通开始、筛选、分页不添加多层确认。

## 4. 任务列表、详情和状态

任务表主要列：任务名/来源、当前阶段、作品与图片页摘要、结束/暂停原因、主要操作。查询和下载可同时发生，状态例如“查找中 · 2 页正在下载”；不能反复把全任务状态覆盖成最后一个线程的文字。

| 状态 | 主操作 | 其他可用操作 |
| --- | --- | --- |
| 等待 | 开始/排到前面 | 编辑未开始草稿、取消 |
| 运行 | 暂停 | 查看本批结果、取消 |
| 正在暂停/取消/收尾 | 显示当前收尾步骤 | 查看结果，不重复提交相同命令 |
| 预算暂停 | 继续下一批 | 调整下一批预算、结束任务 |
| 冷却 | 显示剩余等待 | 暂停或取消，不提供“绕过限流” |
| 需要登录 | 去设置更新授权 | 查看已保留进度 |
| 部分失败 | 查看失败项 / 仅重试失败项 | 查看成功名单、导出 |
| 已完成 | 查看本批名单 | 打开目录、复制为新任务 |
| 存储/恢复故障 | 查看具体问题 | 保留现场、导出脱敏诊断 |

详情展示请求条件快照、已查看范围、页级结果、错误原因和来源信息。UI 不出现数据库表名、内部 phase 代码或原始堆栈，技术细节放可选诊断区。

进度条只有确切分母时才显示百分比；未知总量使用“已检查 X 位 / 已保存 Y 页”。预算进度可以有分母，但标为预算，不当作历史完成度。

## 5. 筛选与其他来源

属性条件采用可操作的复选框、输入框和简短摘要，不做通用可视化规则编程器。最低收藏校验非负整数，AI 三态的未知数量在结果中可查看。字段错误紧邻输入显示，保留已填值。

画师输入支持 ID 列表和能明确解析的 Pixiv 画师链接，显示去重后数量；解析不发网络请求。未知链接格式保留原输入并说明，不对任意网址抓取。

排行榜输入展示中文类型、单日/范围、日期格式提示、采样方式、全任务作品预算；结束早于开始就地报错，可提供交换按钮，不自动改值。实际榜单日期和返回排序进入任务摘要。

搜索显示关键词、匹配方式、请求排序和能力状态。热门无法使用时说明原因；允许回退需明确选择，并在结果写出实际来源。多来源交集各来源分组配置预算，结果展示各组查看数量和未覆盖部分。

下拉内容较多时支持输入过滤本地选项及键盘上下/Enter/Escape；优先复用所选界面技术的能力，避免为单个控件引入成套组件框架。所有来源提交同一种任务命令，不再由子窗口单独启动线程池。

## 6. 下载名单

默认“本批结果”，可切“累计历史”。主要列保持紧凑：作品标题/ID、画师、完成页数、结果、下载时间；选择一行后在详情查看收藏、AI、路径、来源日期/名次及失败原因。

顶部用文字计数切换：新增成功、已有跳过、部分完成/失败、待核验、条件过滤。每项计数来自持久化结果；清日志或刷新 UI 不影响名单。标题搜索/画师搜索只查询本地记录，不回 Pixiv 补请求。

多页作品可展开页列表；例如“2/3 页，p2 失败”比单个红色图标更清楚。列表点击打开原作品页面是用户主动操作，不自动加载网页预览。双击默认查看详情，避免误开一批浏览器标签。

导出显示范围、记录数和目标，成功后可打开文件。保留原有 Markdown，近期 3000 条列表显示范围限制；完整累计名单由数据库按需生成。旧记录无批次归属的归“历史导入”。

## 7. 日志阅读行为

页面底部默认折叠日志，持续显示当前任务、最新重要事件和可展开入口。展开是文字控件，不创建额外采集或日志线程。

- 在底部时跟随最新；用户向上滚动后保持位置，显示“新增 N 条”。
- “清空显示”按事件序号设边界；旧积压不重新出现，磁盘记录不删除。
- “暂停显示”不暂停下载；恢复显示最近窗口与略过提示。
- 级别/关键词过滤注明作用于当前窗口；历史查询或导出明确作用于保留日志。
- 导出按钮称“导出保留日志”，说明是否已轮转截断；不能写“完整会话”却缺开头。
- 切换任务保留各任务的阅读位置和条件。超长消息可展开详情，列表摘要有长度上限。

具体队列、刷新预算和日志保留见 [06](06_RUNTIME_AND_PERFORMANCE.md)。

## 8. 视觉参数与实现限制

以下为候选主题参数，落地前做真实控件截图与对比度核验。

| 项目 | 候选值 / 规则 |
| --- | --- |
| 背景 | 白色主面 `#FFFFFF`；外围/少量分区冷灰 `#F2F5F6`；续跑底 `#F7FAFC`、少量错位底板 `#E8F1F6` |
| 主文字 | `#202B33`；次级说明 `#596A75`，保留清楚字号层次和常规页标题字重 |
| 主要按钮/链接 | `#287EAE`；顶部选中导航用蓝字和细下划线 |
| 分隔线 | `#DCE4E8` 用于分区、`#D8E1E5` 用于边框；输入边界/焦点单独核验 |
| 状态 | 成功 `#316A52`、警告 `#865600`、错误 `#A53030`，同时写状态文字 |
| 字体 | 系统界面字体；标题可少量使用系统宋体；数字/日志可等宽回退，不下载字体 |
| 间距 | 4/8/12/16/24/32 逻辑像素；统一对齐，不靠大量卡片包裹 |
| 形状 | 细线、直角或小圆角、浅色错位底板；主操作和弹出选项可用轻微投影，避免各区都堆阴影以及大面积实时模糊 |
| 动效 | 默认无持续动画；进度更新来自状态，不靠跑马灯模拟活跃 |

文本、输入、选择、表格、滚动的具体实现随技术方案选择；保留可选择文本、键盘操作、焦点和可访问语义，避免把整页退化成不可操作的图片。允许编写必要的自定义样式和控件，但须同时核查复杂度与运行开销。按钮状态、焦点、禁用色与高 DPI 单独验证，不只看静态草图。

## 9. 缩放、窗口与键盘

宽度充足时首页双列；不足时条件区移到主操作下方，正文可垂直滚动，状态栏保持可达。记录表先隐藏低频列，再使用有明确边界的表内横向滚动。导航在窄窗口仍能通过文字菜单/键盘切换。

初始尺寸依据可用工作区，优先恢复合法的用户窗口位置；旧位置在离线屏幕外时收回当前屏幕。不得继续把 1000×860 作为所有缩放场景的硬门槛。目标测试包含 1366×768、1920×1080、100%/125%/150%/200%，窗口可用尺寸以实际 DPI 计算。

Tab 顺序按视觉阅读顺序；焦点始终可见。Enter 只执行当前表单的明确动作，不能在日志搜索中启动下载；Escape 关闭局部展开/对话框，不取消任务。快捷键只提供常用项并在按钮提示中注明，避免覆盖输入法或系统操作。

若沿用 Tk，则保持单根窗口和 after 统一登记/注销；采用其他界面技术时同样明确唯一的界面资源所有者与订阅收尾。关闭详情只解除订阅；退出程序有任务时提供安全暂停后退出或返回，保持收尾进度可见，不在 UI 线程等待后台退出。运行行为以 06 为准，其 Tk 特定细节仅适用于当前候选。

## 10. 页面验收

验证首次/有断点/无权限/断网/限流/空结果/部分失败/已有全跳过；重复点击、切页、改变草稿、取消导出、窗口关闭；高 DPI、键盘、长标题、超大计数和十万模拟记录。图片请求与解码计数必须为零。

先用固定模拟快照覆盖这些状态，再接真实协调器；最终截图必须来自实际运行界面，并注明 DPI、窗口尺寸、数据为模拟或真实脱敏。美化后要重测相同负载响应，不能只验截图好看。

## 2026-10-24 实际交付

主代理完成 Tk/ttk 界面及必要自绘样式；没有新增运行包或图片预览。五个主页面和全部来源已接入统一核心；目录/导出/画师导入使用 Windows 原生弹窗，授权使用遮盖输入弹窗。高缩放窄窗口会把侧栏改为下方并保留滚动；窗口初始尺寸按可用工作区计算。源码、参数校验、实际窗口截图与交互报告见[进度](../REFACTOR_PROGRESS.md)。

当前不持久保存任意窗口坐标、未提交的来源草稿或可调日志保留策略；这些是后续体验扩展，不以设计草图暗示已实现。后台状态刷新、原图质量和任务恢复不依赖这些扩展。
