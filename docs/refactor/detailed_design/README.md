# JpgPng 重构详细设计与实施计划

版本：v7，2026-10-24。状态：下载器主线 P0—P8 已验收并切换；旧历史未导入，E1 正式账号整理 CLI 仍未实现。具体实现边界、测试与清理结果见[实施进度](../REFACTOR_PROGRESS.md)。以下方案保留设计依据，最终交付差异以各专题的实施说明为准。

本组承接 [总体规划](../REFACTOR_PLAN_2026-10-20.md)。用户认可详细设计后已授权实施，并允许替换不合适的旧记录、必要时重新下载；本版据审查改用独立单库账本，旧历史可选导入。技术选择和参数中标为“设计基线”的内容是工程方案，可随实测修正。

## 2. 已确认的产品要求

| 编号 | 用户已确认的要求 | 主要设计位置 |
| --- | --- | --- |
| R01 | 下载质量第一，性能第二，易用性和美化随后 | 02、06、07 |
| R02 | 历史补全与关注新作都保留，默认逐步收全关注画师历史 | 03、05 |
| R03 | 经常新增关注画师，已有进度要能接着用 | 03、04 |
| R04 | 最低收藏、排除 AI 等独立可选，可与下载模式组合 | 03、05 |
| R05 | 保留下载完成后方便查看的名单与历史记录 | 04、05 |
| R06 | 下载界面不做图片预览、不加载缩略图或头像；独立整理任务可按需查看作品样本 | 05、06、08 |
| R07 | 相对路径，尽量项目内实现，少依赖，无单独 Node 环境 | 01、04 |
| R08 | 允许调整整体结构，但业务数据和已有修改须保留 | 04、07 |
| R09 | 参考 IWLTY、21ST 和已有网站研究，结合下载工具实际需求 | 05 |
| R10 | 先规划、详细设计，再分阶段实施；现已授权开始重构，允许替换旧记录 | 本页、04、07与实施进度 |
| R11 | 由 AI 查看每位画师的多张作品后整理真实 Pixiv 关注分组，用户无需逐个整理 | 08 |
| R12 | 用户在 Pixiv 网站检查和调整分组；后续整理尊重网站上的手动变更 | 08 |

“收全”指所选范围内、当前授权可访问、程序支持、符合可选条件的作品。条件关闭时不按该属性过滤。不可访问、未支持类型、未知字段、预算用尽、缺页、失败等都要说明，不能以一个完成百分比掩盖。

## 3. 本轮设计决策

以下默认值是**设计基线**，不是声称用户逐项指定，也不覆盖用户现有配置。

| 决策 | 本版方案 | 原因与调整条件 |
| --- | --- | --- |
| D01 技术路线 | 下载核心复用 Python、SQLite、requests、pixivpy3；主代理已用现有 Tk/ttk 完成可打开的界面候选并实测，未新增依赖；正式联合验收及 P5 长时门槛已通过 | 用户于 2026-10-22 重申允许重构、专门美化代码和少量合理依赖，拒绝为美化堆包/另搭专用环境；零新增包是本次实现结果，不是用户硬性要求。见 05、确认基准与本轮实现记录 |
| D02 调度范围 | 一个程序实例、一个活动批次；其他任务排队；图片页使用有限并发 | 首版避免多个窗口叠加线程和账户请求；以后扩展多个活动批次须保留相同所有权约束 |
| D03 默认入口 | 关注首页默认历史补全，打开页面不自动联网采集 | 与已确认使用习惯一致；恢复具体任务仍沿用它自己的模式 |
| D04 新画师顺序 | 首版沿用现有追加队列，提供“优先补这位”操作 | 不重排已有断点；是否自动优先所有新画师仍可由用户调整，不阻塞底层质量工作 |
| D05 筛选默认 | 沿用已保存值；新配置最低收藏关闭、排除 AI 关闭 | “可选”不等于替用户勾上或关闭既有选项 |
| D06 新任务品质 | 无旧设置时原图、多页开启；已有显式设置迁移时原样显示 | 不静默降级原图；非原图或首图任务不能标成原图全页收全 |
| D07 记录结构 | 新核心采用独立 library.sqlite3 单库；旧三库原件保留、可选只读导入 | 统一任务/游标/成果的数据库事务；不持续双写旧库或全套兼容输出 |
| D08 名单 | 本批结果与累计历史两个视图；文字分页，兼容 Markdown | 保留易读记录，避免靠刷日志找成果 |
| D09 自动化范围 | 用户点开始/继续才启动；预算暂停默认等待继续 | 本轮不增加定时后台采集、自启服务、自动登录或无限续跑 |
| D10 质量能力边界 | 保存源字节并验证传输和可用格式结构；不引入转码或深度解码库 | 文件哈希证明本地身份，不等于与服务器独立校验；必要时再评估深度解码 |
| D11 关注整理扩展 | 项目内独立轻量工具，由 AI 调用、按需看图，用户在网站维护分组；新增运行包目标 0 | 不为整理另建 GUI 或本地模型环境；接口先验证，正式实现排在下载主流程稳定后 |

目录、命名、日志保留天数、并发等沿用合法旧值；新默认与建议上限集中在 04、06，不从草图中的示例数值生成配置。

## 4. 当前事实与设计目标

事实来自源文件、隔离诊断和实施基线中的旧数据库副本汇总检查。未解析真实 Cookie/Token，未检查整个原图库内容。实际库结构健康不等于所有图片已验证。

- 已有 `DownloadTask`、持久化待办、关注画师/页/作品游标、SQLite 页级记录、JSON/Markdown 兼容输出；详见 01 的源码映射。
- 已在模拟响应中复现：HTTP 200 HTML 被报成功；错误起点的 206 在总长碰巧一致时被拼接并报成功。
- 已在离线样例中复现清空日志后积压重现、多行日志突破单次工作量、关闭子窗口时工作线程尚活着等问题。
- 真实性能、会员搜索接口能力、图片库健康度、新界面可用性须按对应工作包验证。E1 的会员分组基础小样见 08，不能替代其他来源的能力验收；历史测试通过数也不是新版本验收结果。
- 2026-10-21 只读检查环境为 Python 3.12.14 / SQLite 3.53.4；未升级环境。部署到其他环境应记录实际版本。
- 初次设计时 GitNexus 未注册本仓库；现已用既有工具 index-only 恢复 ImageTool-Lab 索引，实施按符号执行影响分析，不覆盖项目规则文件。

证据入口：[总体规划的问题清单](../REFACTOR_PLAN_2026-10-20.md)、[质量诊断](../../../../.runtime/jpgpng_refactor_20261020_follow_first/quality_results.json)、[日志等行为诊断](../../../../.runtime/jpgpng_refactor_20261020_review/probe_results.json)。

## 5. 最小完整交付路径

```mermaid
flowchart LR
    A["保护基线与接口约束"] --> B["原图与落盘正确"]
    B --> C["持久化任务与恢复"]
    C --> D["关注历史 + 可选筛选 + 名单"]
    D --> E["日志与性能验收"]
    E --> F["轻量界面接入"]
    F --> G["其余来源统一与切换"]
```

首个可交付闭环：关注历史任务 → 组合筛选 → 原图全页 → 暂停/重启续跑 → 本批名单 → 缺页重试。排行榜等入口保留现有能力，后续接入统一流程；不能在尚未接入时删除旧入口。

独立扩展 E1 的顺序为：纳入计划 → 小样技术验证 → 工具实现 → 分类小样 → 分批整理及下载联测。它不改变 P0—P8 主线编号，不作为核心下载器完成的必经前提；后续启动范围以用户的新任务和实施进度为准，E1 的推进不自动解除主线停止边界。

## 6. 尚需实测或评审的事项

| 事项 | 当前处理 | 最迟解决阶段 |
| --- | --- | --- |
| 新画师是否自动优先 | D04 为兼容默认；保留用户调整空间 | 关注界面接入前 |
| 实际 CDN 返回的长度、ETag、内容格式 | 02 定义严格分支，先模拟后小样 | 文件协议切入生产前 |
| Premium 能力与 App/网页身份是否一致 | 状态为“未验证”，不靠付费身份推断接口已可用 | 搜索接入验收 |
| 旧绝对路径、待办版本与断点是否可映射 | 用副本迁移并对账；不猜路径或身份 | 数据写入切换前 |
| 视觉方向与布局 | 用户已确认两张基准图的风格，并允许布局优化与适量阴影；实际窗口尺寸随可用空间适配 | 按 05 和确认基准对照实际运行效果 |
| 吞吐、刷新预算、日志容量 | 06 给可测起点；在同机同负载下校准 | 性能验收 |
| 不支持的作品类型、未知图片编码 | 明确列出并保留原因，不伪装成空画师 | 来源与文件协议验收 |
| 关注分组登录接入、读写、数量与多组限制 | 基础浏览器同源读写已验证；正式可重启入口、完整盘点和服务端限制仍待落实 | E1-2 工具实现，见 08 |
| 分类维度、样本充分性与人工调整保护 | 候选规则先做十来位画师的小样；样本数为设计基线 | E1-3 小样验收，扩大批量前 |

这些事项不要求现在逐项追问用户。能由离线实验解决的由实施验证；会改变收集偏好或明显增加依赖的，再给出具体结果讨论。

## 7. 文档维护规则

1. 产品意图以用户明确要求及总体规划为准；实现细节以本组对应专题为准。冲突先记录并修正文档，不能借“默认”改变用户要求。
2. 每个工作包关联 R 编号和验收编号。完成时填写证据路径、实际运行结果、剩余限制；未执行不写“已通过”。
3. 当前设计就地修订，版本变化写本页；历史诊断与备份不覆盖。新增专题必须有独立责任，避免再复制一份大纲。
4. 文档使用 UTF-8 无 BOM、LF，相互链接使用相对路径。此目录不放凭据、真实名单或运行数据库。
