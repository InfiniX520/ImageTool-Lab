# 06 运行、日志与性能

版本：v2，2026-10-21。状态定义见 [01](01_ARCHITECTURE_AND_CONTRACTS.md)，关键持久化见 [04](04_RECORDS_AND_MIGRATION.md)。设计目标和当前实现边界分开记录；P5 尚未验收，已执行和未执行的测量以[实施记录](../../../../docs/maintenance/2026-10-21_jpgpng_refactor_p5.md)为准。

## 1. 资源所有权

| 所有者 | 资源 | 生命周期 |
| --- | --- | --- |
| UI 主线程 | 唯一 Tk 根窗口、控件、after 订阅 | 程序启动至所有业务安全退出 |
| 协调器线程 | 活动批次、控制命令、请求预算、状态快照 | 程序生命周期；每次最多一个活动批次 |
| 来源工作者（1） | 当前来源分页与受控详情请求 | 批次内受调度，不由子页面创建 |
| 页下载工作者（N） | 各自 HTTP 会话、流式缓冲、页控制令牌 | 程序内复用或批次结束有序回收；N 是全局上限 |
| 数据写入工作者（1） | 新账本一写连接、短事务；旧历史仅在显式导入时读取副本 | 业务停止并确认队列提交后关闭 |
| 短查询工作者（1） | 短只读连接、有界分页结果 | 与导出分离，短查询队列默认 8，满即拒绝 |
| 导出工作者（1） | 固定快照、流式输出、同目录临时文件 | 最多 1 个活动及 1 个等待，取消独立传播；避免长快照占用短查询工作者 |
| 诊断写入工作者（1） | 有界日志队列、文件轮转 | 业务关键收尾结束后最后关闭 |

不为每个 job 建一组线程，不为每个页面再建 logger。所有 Session 由持有者关闭；全局 `close_all` 只在所有使用者退出后执行。数据工作者不在持锁状态回调 UI 或等待网络。

Tk 事件处理必须短，长操作拆分或放工作线程，保证主事件循环能持续处理输入。[Python Tkinter 线程与事件循环说明](https://docs.python.org/3.12/library/tkinter.html#threading-model)

UI 发送命令采用非阻塞入队，满时立即显示“操作正在处理”，不冻结窗口。后台到 UI 使用纯数据快照；只有主线程执行 Tk 调用和 after 注册。持久化确认可阻塞业务工作者，但等待须可取消、可显示故障，不占 UI 线程。

## 2. 容量与参数起点

| 项目 | 新配置起点 / 边界 | 满载行为 |
| --- | --- | --- |
| 活动批次 | 1 | 其余排队 |
| 页下载并发 | 3；首轮校验 1—8 | 保留合法旧值；超出已验证范围明确提示调整，不静默改 |
| 页任务内存队列 | 64 个 ID，不含图片正文 | 来源减速；已持久化待办留库，不丢任务 |
| 传输块 | 当前实现固定 64 KiB/工作者 | 流式处理，不整图缓存；未以扩大块获得性能成绩 |
| 片段检查点 | 新增 8 MiB 或经过 5 s；正常检查点至少间隔 1 s，暂停/完成立即保存 | 先同步文件，再提交确认偏移；异常恢复不信任未确认尾部 |
| 持久化命令 | 128 条且总载荷 ≤8 MiB | 业务生产者等待确认，存储故障阻止新派发 |
| UI 控制命令 | 32 条，重复 command_id 合并 | 非阻塞拒绝重复/过量命令；暂停退出有独立控制标志 |
| UI 状态 | 每个活动对象保留最新 revision | 替换过时进度，不逐条堆积 |
| 诊断日志队列 | 1024 条且 ≤4 MiB；单条摘要 ≤16 KiB | 优先合并/舍弃 debug/info，记录缺失数量与区间 |
| UI 日志窗口 | 3000 行且 ≤2 MiB，以先到者为准 | 丢最旧显示内容，磁盘保留策略独立 |
| 单次日志刷新 | ≤8 ms、≤100 行、≤32 KiB，任一达到即让出 | 长消息分块到下次，不按消息条数冒充工作量 |
| 活跃刷新周期 | 100 ms；空闲可放缓至 250 ms | 仅变更区域刷新；折叠日志不更新隐藏文本 |
| 记录分页 | 默认 100，最大 200 行 | 超出必须翻页，不建全量行控件 |
| 连接/读取超时 | 5 s / 15 s 起点 | 在取消、重试和限流策略中统一使用 |
| 单页交付周期 | 当前总尝试最多 3、整个周期墙钟预算 300 s；5/15 s 连接/单次读 | 取消与块间 deadline 检查；早期每次目标 120 s 未作为独立强制上限实现，公网校准留在 P8 |
| 关注新配置预算 | 每批 30 位画师、80 次查询请求、100 个新增/补齐作品 | 沿用合法旧保存值；实际请求含重试/详情 |

源码中的 FetchConfig、GUI 回退值与使用说明已有不一致的预算默认（例如请求 500 与 80）。实施应统一单一默认来源，并用配置迁移测试防止覆盖用户保存值；本表不是声称现有程序已经统一。

单次异常大来源响应也要有大小/候选数量限制；不得静默截断并推进游标。若现有 API 库先完整解码，响应前限额需要在适配层落实并实测，不能仅给规范化结果设上限就宣称全链路内存有界。

## 3. 限流、取消和重试

同账户查询共享速率与冷却；CDN 传输限制独立但可受同一账户风险停止影响。每个真实请求、重试和必要详情都记账；来源子模块不再独立追加隐藏请求预算。

冷却使用可取消等待与单调时钟；UI 显示由 UTC retry_at 换算的剩余时间。遵守 Retry-After；没有时按现有退避策略，有总尝试上限。认证失效、验证要求、持续权限错误进入需要处理状态，不自动循环换入口试探。

读取超时约束单次读，不能冒充整个 HTTP 请求的总耗时上限；传输还需墙钟 deadline 与块间取消检查。DNS、系统调用等实际阻塞边界要在真实环境记录；超时仍未退出时显示收尾未完成，不宣称线程已销毁。

## 4. 暂停、批次结束与退出

### 4.1 用户暂停

1. UI 立即确认“正在暂停”；协调器停止新来源查询与页任务派发。
2. 来源在可确认边界保存候选/游标；下载工作者检查令牌，保存已确认片段。
3. prepared/记录提交中的交付完成幂等收尾，不向下一个作品扩展。
4. 数据写入队列确认，活动工作者不再写该批次，生成本批结果后进入 paused。
5. 继续时创建新批次，重新计本批预算，恢复同任务未决项。

预算结束与用户暂停不同：来源预算用尽可排空已接收的有限下载队列再暂停，UI 写“本批查找结束，正在保存已接收作品”。用户主动暂停要尽快退出当前传输，不排空全部待办。

### 4.2 取消与关闭

取消停止未来工作，保留图片、记录和取消时的待办/片段；不自动删除片段。若要继续取消任务，可复制未完成范围成新任务。关闭任务详情只解除视图订阅。

退出程序：停止接受新命令 → 安全暂停活动批次 → 确认来源/下载工作者退出 → 提交记录 → 完成必要投影或标记待恢复 → 关闭业务连接 → 刷新并关闭日志 → 取消 after → 销毁 Tk。UI 期间仍能展示阶段。

总收尾目标为 20 s 内完成常规可取消情形；超过该值显示当前阻塞点，并继续等待或允许返回界面。用户若最终选择强制退出，要明确保留最后已提交状态且下次走中断恢复；不能通过 daemon 线程退出制造“正常完成”结果。

程序以操作系统文件锁保护同一项目写入实例，锁文件可放 `download_logs/.writer.lock`；进程退出释放锁，不靠 PID 文件存在与否判断。第二个实例不启动另一个写入器，可提示已有实例和提供只读诊断。迁移同样持此锁。

## 5. 日志三条路径

| 信息 | 落点与可靠性 | 不能做什么 |
| --- | --- | --- |
| 文件/待办/断点事实 | 业务数据库及交付凭据，提交确认后发布 | 不以日志文本代替 |
| 关键任务事件 | task_events，状态转换可恢复 | 不因日志队列满而舍弃完成/暂停事实 |
| 高频诊断 | 有界队列 → 专用日志线程 → 轮转文件 | 不无限堆内存，不堵住取消通道 |

日志事件包含 `session_id、sequence、UTC 时间、job/batch、level、code、safe_message、work/page?`。sequence 在单会话单调增长；session_id 使用随机唯一标识，时间+PID 仅用于可读文件名。

进度事件可以合并，debug/info 可以按容量丢弃并汇总“略过 N 条”；warning/error 优先写入。业务故障必须先持久化到任务状态，诊断满载时仍可查。磁盘日志失败使用有限内存故障摘要并在 UI 常驻提示；若同时是业务存储空间不足则停止新下载。

写入线程按时间/字节批量 flush；严重错误请求尽快 flush，但业务线程不直接同步写日志文件。日志文件写满不重建无限缓存。关闭以独立停止标志配合队列排空，不能因投递一个结束哨兵被满队列卡死。

## 6. 日志显示、脱敏与保留

### 6.1 清空、阅读与迟到数据

“清空显示”记录当前会话序号高水位；消费时拒绝所有小于等于该序号的积压事件。过滤条件变化或多行分块也不得让旧消息复活。

用户向上滚动后不 `see(end)`；新增计数与显示缓存分开，点击恢复跟随才回到底部。暂停显示期间只保留有界窗口，恢复时解释略过范围，不补绘数十万旧行。查询结果和 task snapshot 都带请求版本，旧版本返回不能污染当前页面。

### 6.2 脱敏

事件先选取允许字段，再集中脱敏，不依赖一个正则覆盖所有秘密形式。Cookie、Token、Authorization、请求头、响应会话正文、含秘密的查询参数不写日志。异常栈可以保留函数定位，相关值必须替换；诊断截图也不能显示输入框明文。

保留原图来源地址须确认无敏感查询部分；有临时访问参数的地址只在必要的本地任务恢复数据中处理，公开导出使用作品链接或脱敏标识。账户状态只展示身份摘要和验证结果。

### 6.3 轮转与导出

新日志可放 `runtime_logs/v2/` 由明确清单管理：单卷 10 MiB、当前会话最多 5 个备份，管理目录总预算初值 256 MiB、最长 30 天，任一触发时只轮转已关闭且属于该策略的旧诊断文件。旧历史日志、用户导出、业务记录和备份不纳入自动清理。

活跃文件不删；空间无法满足时显示日志受限并按有界丢弃策略处理。目录清理须验证解析后的路径和所有权，拒绝链接越界。策略值在设置中可见，保留量不是“永远完整”。

导出冻结保留分卷清单与序号范围，防止边轮转边读丢文件；通过短期引用保护或先建立可核验的导出快照，完成后释放。导出注明起止时间、序号缺口、轮转截断和丢弃计数，后台流式且可取消。

## 7. 性能测量与门槛

同一机器、同 DPI、同模拟响应和原图/多页设置比较。日志写入、数据提交与文件校验不能为跑分快而关闭。

| 场景 | 初始验收目标 | 记录证据 |
| --- | --- | --- |
| 点击、切页、暂停反馈 | p95 ≤100 ms，常规样例无连续 500 ms 冻结 | 事件进入到绘制/状态反馈时间 |
| 日志刷新 | p95 ≤8 ms，p99 ≤16 ms；容量始终受控 | 刷新耗时、行/字节、峰值积压 |
| 日志压力 | 1 万突发、持续 1000 条/s、400 条各 100 行仍可操作 | 短/长/多行/重复错误独立样例 |
| 启动 | 暖启动 ≤2 s，冷启动 ≤5 s 出现可操作界面 | 不含登录网络等待；至少多次测量 |
| 空闲 | 无装饰循环；单核等效 CPU <2% 的目标 | 60 s CPU 时间差、线程/句柄数量 |
| 十万记录 | 默认页本地查询 p95 ≤200 ms，界面更新 ≤300 ms | SQL 耗时、控件数、缓存大小 |
| 连续运行 | 2 h；预热后无未解释的线性内存增长 | 每分钟 RSS/队列/句柄，最后 60 min 正斜率目标 ≤0.5 MiB/min |
| 多轮任务 | 50 次开始/暂停/继续/查看详情后资源回到稳定区间 | 存活线程、会话、after、连接计数 |
| 下载 | 相同限速和字节输入下统计请求数、吞吐、CPU/磁盘 | 普通完整下载不额外探长度；不承诺公网倍速 |
| 导出 | 大于 UI 窗口的记录/日志可流式导出并取消 | 峰值内存、取消反馈、旧成品保留 |

如果 FULL 提交、哈希或结构检查影响吞吐，优先合并短事务、复用元数据、减少多余 IO；不通过关闭校验来满足性能指标。所有阈值调整须有原始样本与理由，不把降低门槛当优化。

测试优先使用已有 pytest、标准库模拟 HTTP/SQLite/Tk 和 Windows 进程指标，不为测量另装庞大依赖。仅文档变更不执行这些业务负载；对应运行安排见 [07](07_IMPLEMENTATION_AND_ACCEPTANCE.md)。

## 8. P5 候选的具体边界

App 元数据传输默认最多 8 MiB 编码正文和 8 MiB 解码正文、30 s 墙钟检查，gzip 按 64 KiB 块限额解码后再交现有 SDK；重定向与 adapter 重试关闭。429/503 的安全冷却事实持久化到同账号事件，新批次及重启后先检查冷却，不自动补发请求。DNS/系统阻塞仍以真实超时收尾状态为准。

日志生产者与 UI 状态只持有内存条件锁；轮转、删除、历史文件检查与导出保护使用独立存储锁，磁盘慢不能拖住 emit/snapshot。默认每会话保留当前卷和 5 个备份；无法删除或分卷受导出保护时，内存及本会话受管分卷有 16 个的额外硬上限，达到后降级并计数丢弃诊断，不持续创建新卷。manifest 在 JSON 解码前限制为 2 MiB；异常清单不作为删除未知文件的依据。

日志显示按物理行保留待续部分，旧待续未处理完就不读取更新事件。单行超过一次完整刷新字节预算时只在显示端明确截断，文件事件仍按消息上限保留；不足以放下完整截断标识的极小预算使用 ASCII 占位。清空记录当前序号高水位。日志 close 的文件/清单/保留收尾也由原有唯一写入者完成，超时返回 False，运行时保留“正在关闭”，不能提前宣告完成。

P5 使用真实 Tk Text 的隐藏测试窗口测操作耗时，不把它说成最终界面绘制/启动/点击成绩。P6 仍须验证完整页面、DPI、after 和交互。十万记录索引、日志丢弃、50 次生命周期及长时运行保留原始样本；尚未完成的 2 h 运行不因启动了进程而记作通过。

## 2026-10-24 验收结果

candidate_main06 的 stability07 完成连续 7200.0 秒离线运行，源码摘要不变。最后一小时 RSS/私有内存斜率分别 0.019415/0.017334 MiB/min；60 秒空闲单核等效 CPU 为 0.962%，关闭后只剩 1 个 Python 主线程。此前中断片段不累计。本长测覆盖固定运行时拥有者、SQLite、有界日志及隐藏 Tk Text，不冒充最终页面连续渲染成绩。

另外完成 50 次启停/暂停/继续、持续 1000 条/s 与突发/多行日志、十万条本地记录查询及导出；真实界面另测切页、布局、来源任务与安全关闭。API 与图片请求各用共享节拍控制，沿用合法旧间隔，当前并发与间隔修改在下次打开时生效，不另外增加线程或无限队列。详细分布和失败历史保留在[原始报告](../../../../.runtime/jpgpng_refactor_20261022_p7_integration01/)。
