# 07 实施计划与验收

版本：v6，2026-10-21。本文定义任务与验收标准，实际状态和证据见[实施进度](../REFACTOR_PROGRESS.md)。单库与可选历史导入取代早期的强制三库迁移路线；用户已另行明确恢复主线，P3/P4 离线核心已验收，E1 仍按独立阶段推进。

## 1. 实施原则

先封住已确认的错误图片/续传路径，再建立任务与文件提交闭环，随后完善关注、名单、运行性能和界面。每个工作包保持当前入口可用，或通过隔离开关验证；未接入的新来源不能替换旧入口。

只对实际行为、失败边界和回归风险编写测试，不以给每个 getter 或文档增加测试凑覆盖率。现有测试结果需要重新运行确认；与正确质量语义冲突的旧测试应明确替换，不能保留错误期望让新实现迁就。

```mermaid
flowchart LR
    P0["P0 基线"] --> P1["P1 已确认质量缺口"]
    P1 --> P2["P2 契约与持久化"]
    P2 --> P3["P3 完整页交付"]
    P3 --> P4["P4 关注与名单"]
    P4 --> P5["P5 日志与性能"]
    P5 --> P6["P6 原生界面"]
    P6 --> P7["P7 其他来源统一"]
    P7 --> P8["P8 真实小样与切换"]
```

这条顺序表示验收依赖，不禁止在前序稳定后补做后续设计。真实小样可在相关离线门槛通过后按范围提前验证，不能拿真实采集替代故障注入。当前不承诺日历工期；P0 完成后按实际改动量再估算。

## 2. 工作包

### P0：保全与实施准备

- **输入**：当前工作树、本组详细设计、已确认需求。
- **工作**：建立新的源码/配置/库版本基线；核对入口和有效配置优先级；恢复当前仓库 GitNexus 查询，按 AGENTS 对待改符号执行 impact 并报告影响。准备隔离根目录、模拟账户/响应和数据副本。
- **边界**：不重置已有修改，不清理业务数据；源码分析和副本验证不触发登录/采集。备份含敏感配置时只保存在保护位置。
- **完成条件**：基线可重算、旧入口离线启动可达、测试不会读写正式库、影响范围可解释；没有声称本轮文档基线替代实施基线。
- **回退**：未改业务数据，无需数据回退。

### P1：修复已确认的质量缺口

- **主要位置**：`core/download_engine.py`、`core/download_service.py`，对应回归测试。
- **工作**：200 错误正文拒绝、状态/内容编码/长度检查、取消优先于重试；保留现有门面返回类型。尚无可信片段与强版本凭据时，先禁用旧 Range 拼接、拒绝未请求的 206/Content-Range；完整起点/区间检查随 P3 的安全续传协议实现。
- **范围**：先在现有链路完成可独立交付的检查；完整 prepared/receipt 协议依赖 P2/P3，不在此虚称完成。
- **测试**：正确/错误 HTTP 响应、取消、多页元数据与已有记录兼容；用本地模拟响应复现此前两个质量缺口。
- **完成条件**：错误正文及错误续传不产生成功结果，正常已知原图路径仍通过，失败证据清楚。
- **回退**：仅代码回退；若已经形成新格式临时文件，保留识别说明，不把它们当垃圾删除。

旧测试 `test_download_file_resume_returns_true_when_local_size_matches_expected` 要改成明确区分“有可信完成凭据”和“仅大小相等”：后者不再允许成功。这是修正错误契约，不是删除困难测试。

### P2：任务契约、持久化与最小调度

- **主要位置**：候选 task_contracts、library_repository、task_coordinator、路径适配；旧记录只读导入另行实现。
- **工作**：实现 01 的任务/批次/页标识与不可变请求，04 的新单库、命令幂等、接收与游标同事务、单实例锁、一个活动批次和有界队列。实现最小安全暂停，UI 暂由旧入口适配。
- **历史处理**：新库从空库即可验证，不强制先迁移旧库。P2 验证旧原件不被触碰、未知/不兼容结构拒绝写入；可选历史导入器在 P8 单独演练和验收，不拖住新核心。
- **测试**：同一命令重复提交、候选接收后队列满、事务回滚与崩溃重放、输出身份、换路径、停止命令与有界写入收尾。
- **完成条件**：持久待办不丢、游标不领先、重复恢复不重复记账；新库与旧原件隔离，未切换真实业务库。
- **回退**：副本可丢弃重建；生产切换如已发生，必须按 04 保全新增数据后成套回退。

### P3：完整的页交付与恢复协议

- **主要位置**：下载 engine/service、页执行器、record_manager/repository、任务存储。
- **工作**：单次多页展开、同目录临时文件、版本化续传、流式摘要/格式校验、prepared → 发布 → receipt → 确认，恢复只检查未决文件。
- **测试**：在每个持久化/文件操作边界强制中断；验证磁盘满、权限拒绝、正式目标出现冲突、主库成功但确认失败、未知长度、混合格式与缺页。
- **完成条件**：满足 02 的文件/记录/统计三方结果；所有错误分支不把半文件或伪图片记为完成；旧可信记录对应被搬走文件仍正常去重。
- **回退**：新交付只由兼容版本恢复，不能启动旧写入器误读新待办；提供版本匹配说明。

### P4：关注历史、新作、可选筛选与名单闭环

- **主要位置**：follow_crawl_service/state、fetcher queue/follow、统一过滤/来源适配、记录查询与导出。
- **工作**：历史为默认、现有起点模式保留、关注快照增量及断点确认、筛选独立组合、规则放宽补查、每批预算与作品/页统计；本批结果和累计历史查询、Markdown 输出。
- **测试**：新画师、取消/重新关注、换序、未完整快照、页面变化、扫新锚点缺失、字段未知、规则变化、跨批失败恢复、旧记录导入与实际批次归属。
- **完成条件**：隔离样例能连续演示“开始 → 暂停 → 重启 → 继续 → 查看名单 → 仅补失败页”，结果能解释，已下载不重复。
- **回退**：保留旧入口和原记录；新 schema 由统一适配层保护，不让旧路径绕过。

### P5：日志、资源与性能

- **主要位置**：logger、任务协调器、HTTP 会话所有权、GUI 日志适配和事件订阅。
- **工作**：有界日志双通道、清空序号边界、滚动位置、唯一会话文件名、轮转/导出一致性、后台收尾、队列背压和可取消等待。
- **测试**：多行日志、持续压力、磁盘日志故障、队列满时暂停/退出、同秒创建会话、导出并发轮转、50 次启停和 2 h 离线运行。
- **完成条件**：达到或以实测理由校准 06 的门槛；校准不能降低正确性，内存/线程/句柄增长可解释。
- **回退**：保留日志调用门面；若回旧日志显示，也不能回退已完成的下载事实协议。

### P6：轻量原生界面接入

- **主要位置**：main_controller/view、主题、页面与 GUI mixin 适配。
- **工作**：先用模拟快照完成 05 的布局和状态，再接协调器；关注主操作、可选条件、任务详情、名单和折叠日志可用；移除视图自己的工作池。
- **测试**：键盘、缩放、窄窗口、离屏窗口恢复、长文本、各种空/错误/运行状态、迟到查询、重复操作；确认零缩略图/头像请求和零图片解码。
- **完成条件**：真实 Tk 截图与交互记录可评审；相同压力下没有因美化新增明显卡顿，不新增运行依赖。
- **回退**：视图开关回旧 UI，核心服务和数据协议保持已验收版本；不是把旧整套程序重新指向新库。

### P7：排行榜、会员搜索、推荐与交集统一

- **主要位置**：fetch_strategies、search/ranking mixin、multi_filter_fetch 与其他来源页面。
- **工作**：来源独立参数/游标、排序透明、合法空结果、排行跨日期名额、实际日期与来源出现、有限交集覆盖说明，全部复用任务/下载/记录边界。
- **测试**：日期边界、空榜/请求错误、相同作品多次出现、未知会员能力、排序失败/明确允许回退、交集无结果/预算终止/恢复。
- **完成条件**：相同请求从不同入口进入得到相同语义和统计；旧能力全部有对应入口与测试，不以“界面简洁”为由删除。
- **回退**：每种来源单独切换适配，不影响已验收关注主流程。

### P8：真实小样、迁移切换与交付

- **前提**：相关离线用例通过、生产备份可恢复、用户进入实际实施/验证范围后执行；本轮写文档不触发。
- **工作**：现有授权下小量验证原图、多页、关注新增/续跑、实际榜单和会员排序能力；按用到的功能分别设预算，出现验证要求或明确限流按策略停止。记录实际来源与结果，不输出秘密。
- **耐久与迁移**：同机负载对比、临时副本换路径、备份恢复、部分迁移/部分文件提交恢复、导出对账。可选历史导入单独使用旧库一致性副本，验证计数、路径映射、legacy_trusted 等级、来源摘要幂等和中断续接；未选择导入也应能完整运行。
- **完成条件**：必要真实行为有证据；生产切换前有版本匹配回退方案，用户启动/使用说明与实际入口一致，所有旧入口退役都有引用核查。
- **收尾**：不自动清理数据库、原图、备份和未决片段，不盲目提交整个已有脏工作树。

### E1：关注画师整理（独立扩展）

- **需求**：R11、R12，以及 R01/R06/R07 的质量、资源与路径约束。
- **定位**：JpgPng 内独立运行的轻量工具；AI 查看多张作品后判断分组，结果写回 Pixiv，用户在网站检查和调整。完整范围与 F01—F10 验收项归属 [08 扩展计划](08_FOLLOW_ORGANIZER_EXTENSION.md)。
- **阶段**：E1-0 纳入计划 → E1-1 小样技术验证 → E1-2 工具实现 → E1-3 分类小样 → E1-4 分批整理及下载联测。各阶段输入和完成条件在 08 定义，实际状态只在实施进度维护。
- **依赖**：E1-1 可在单独安排后提前验证；E1-2 排在 P3/P4/P5 的下载主闭环与性能门槛稳定后。E1-4 联测需下载侧与整理侧分别通过相关验收，可随 P8 或后续扩展批次进行，不阻塞 P0—P8 核心交付。
- **执行边界**：E1-0 当时仅做计划文档；后续用户要求继续，才进入 E1-1 的小样验证。临时接口验证不代替正式工具、分类和故障恢复验收；主线原先停在 P2，后续用户另行明确授权从 P3 恢复，历史停止记录保持原样。
- **验收分层**：先验证接口能力，再运行模拟故障/恢复检查和真实分类小样，最后联测；不以重构结束时一次大规模实跑代替分层验证。

## 3. 验收矩阵

每个用例至少记录输入、预期、实际、关联工作包、证据位置、是否联网。`未执行 / 通过 / 失败 / 不适用及理由` 四种状态，不能只打勾。

| 组 | 必须覆盖的场景 | 断言 |
| --- | --- | --- |
| T01 请求 | 参数无效、双击、保存设置变化、运行中编辑草稿 | 无副作用验证、命令幂等、快照不变 |
| T02 原图 | 元数据完整/缺失、p0 与其他页不同扩展名、只能拿到预览 | 使用精确原图或明确失败，无静默降级 |
| T03 响应 | 200 HTML/JSON、伪 MIME、空文件、格式不支持、未知长度 | 验证等级准确，无假成功 |
| T04 Range | 正确/错误起点、缺头、区间长度错、部分剩余区间、200/416、版本变更 | 不误拼接，不凭同尺寸报完成 |
| T05 文件 | 磁盘满、目标冲突、路径越界、临时文件被改、杀进程 | 用户文件不被覆盖，恢复有依据 |
| T06 持久化 | 每个 prepared/rename/receipt/确认边界故障 | 文件/主库/待办可对账，重放不重复 |
| T07 多页 | 三页只完成一页、失败后重试、首图改全页 | 只补缺页，作品/图片计数准确 |
| T08 旧数据 | 文件被搬走、重复 ID、旧时间未知、旧 AI 值不明 | 保留兼容，不能编造验证或批次归属 |

| T10 分页 | 页内位置中断、作品插入/删除、锚点消失、长时间不运行 | 不跳过未持久化项，覆盖不确定如实显示 |
| T11 筛选 | 无/单/多条件、未知字段、边界收藏数、规则放宽/收紧 | 可组合，补查被过滤范围，旧图片不删除 |
| T12 预算 | 恢复待办、页中用尽、重复作品、失败占名额 | 名额与请求不同，预算暂停不称收全 |
| T13 排行 | 跨月/闰日/反向范围/未发布/空榜、跨日重复 | 实际日期与全局上限准确 |
| T14 搜索 | 会员已验证/未验证、热门失败、首屏低收藏、允许回退 | 请求意图与实际排序可查，不隐藏改源 |
| T15 交集 | 有/无交集、有限样本、一个来源失败、恢复重放 | 覆盖声明正确，不重复交付 |
| T16 名单 | 本批/累计、跨批重试、跳过/过滤/缺页、导出取消/失败 | 新增归属准确，可读旧记录保留 |
| T17 生命周期 | 关详情、暂停、取消、退出、队列满/网络阻塞 | 无提前销毁资源，收尾状态真实 |
| T18 日志 | 清空积压、阅读旧消息、长/多行、轮转导出、满盘 | 不跳动、不复活旧日志、不虚称完整 |
| T19 界面 | 高 DPI、窄屏、输入法、长文本、迟到结果、反复切页 | 主要操作可达、焦点正确、线程不叠加 |
| T20 性能 | 十万记录、1 万日志突发、持续 1000/s、2 h、50 次启停 | 06 的原始指标与容量边界满足 |
| T21 路径 | 不同 cwd、项目改名/换盘、中文空格、外部根、冻结入口 | 无硬编码依赖，身份映射稳定 |
| T22 迁移 | 新库空启动、可选旧记录导入、未知版本、部分提交、备份恢复、新成果后回退 | 不强制兼容旧写入，保全新旧数据 |
| T23 保密 | 模拟 Cookie/Token/认证异常/带秘密 URL | 日志、名单、截图无秘密；只用假凭据测试 |
