# 下载、原图与关注续跑历史

本文合并下载重试与页级审计、关注画师可恢复任务、原图元数据与持久化交付修复、正式续跑记录。合并前原文已保存在清理前归档中。

## 问题基线

历史实现曾存在以下风险：

- “下载失败”日志只代表一次尝试，却容易被理解为最终失败。
- 作品 ID 或 `p0` 已存在会遮蔽多页作品的缺页。
- App API 已返回的 `meta_pages` 原图地址在队列边界被丢弃，迫使每个作品访问 Ajax。
- 非零残片可能被直接视为完整文件。
- 画师遍历完成早于下载任务真正交付，异常退出时任务可能丢失。
- 关注全部总从第一位开始，后半段更容易遇到断流或 429。

## 下载链路修复

- `DownloadTask` 携带完整原图 URL、已知页数、画师和下载选项，同时保留旧 11 元组兼容。
- 正常路径直接使用 App API `/img-original/`；Ajax 仅作共享限速、single-flight、退避和可取消的兜底。
- 每页结果分为下载成功、最终失败、已完整跳过和重试恢复；作品汇总与图片页汇总分开。
- 多页作品逐页核对数据库、文件路径和大小，历史缺页会重新入队。
- outbox 在入内存队列前写 SQLite，成功删除，失败/崩溃保留并在下次启动优先恢复。
- 日志每秒 flush，警告/错误立即 flush；兼容 JSON 通过事件游标检测并恢复。

## 关注画师可恢复调度

关注任务使用 `follow_crawl_state.sqlite3`，与下载记录主库隔离。画师 ID 是稳定键，序号只用于交互；配置指纹隔离不同任务语义。

支持：

- 智能续跑、从头开始、指定序号、指定画师 ID、仅重试未完整画师。
- 画师/API 分页/页内作品三级断点。
- 每批画师上限、API 请求预算和下载队列预算。
- `Retry-After`、指数退避、认证错误终止和可取消等待。
- 关注列表增量同步：新增画师追加，取消关注画师进入终态，不完整快照不误删。
