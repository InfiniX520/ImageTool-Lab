# 归档验收与演练

日期：2026-11-11。状态：待实施测试清单。本轮只验证设计文档，下面所有产品测试均尚未执行。

## 1. 分层验证与实际样本

| 层次 | 输入 | 目的 | 用户配合 |
| --- | --- | --- | --- |
| L0 设计检查 | 文档、当前源码与旧记录 | 路径、历史保全、决策一致性 | 当前无需配合 |
| L1 纯离线 | 生成文件、普通图片、临时库 | 清单、容量、状态机、取消与恢复 | 无需取回图库 |
| L2 工具离线 | 固定来源工具、专用测试密码、隔离副本 | 实际加密/解密、损坏修复、安全输入 | 仅在工具/密钥交接需要时配合 |
| L3 夸克真实小样 | 约几百 MiB–2 GiB 的无敏感测试数据 | 官方客户端上传→取回→完整核验 | 用户选择远端位置、上传并下载测试对象；不提供账号密码 |
| L4 实际收藏小批 | 用户选定且保留源文件的一小批 | 索引、恢复、文件变更和真实流程 | 明确选定范围，仍不先全量取回 |
| L5 空间释放 | 已通过全部前提的具体清单 | 仅释放所选原件，重启可对账 | 执行产品中的本批释放动作 |

本轮完成的是 L0；不能将网页查到工具有某功能计作 L2 通过。每层至少有一个真实端到端路径，mock 用于异常注入，不能全靠 mock 得出可恢复结论。

## 2. 离线验收矩阵

### 2.1 输入、清单与原件

| 用例 | 必须结果 |
| --- | --- |
| 单页、多页、不同格式原件 | 解包后每个成员大小/SHA-256 与冻结输入一致；无重编码 |
| 旧文件没有下载摘要 | 只建立当前基线，来源等级不伪造 |
| 源在读取/冻结期间变化 | 拒绝不稳定结果；不将不同版本混成一件成功作品 |
| 原图已有摘要但实际不符 | 保留冲突，不能用新摘要覆盖原期望 |
| 文件名含 Unicode、空格、引号、前导 `-` | 参数和清单解析安全，不作为开关或 shell 命令执行 |
| Windows 大小写碰撞、设备名、ADS、尾点/空格、超长路径 | 不覆盖、越界或静默丢项；可恢复名称映射明确 |
| 链接、junction、硬链接、输出目录嵌套于源目录 | 拒绝越界/自摄取，正确计算实际对象与空间 |
| 下载正在写入、半成品与数据库/凭据混在源目录 | 不误纳入原件清单，明确排除原因 |
| 一件作品/文件超过目标包大小 | 单独规划并检查能力，绝不截断图像 |
| 清单非常大 | 有界分页、数量/大小限制，超限明确暂停而非截断 |

### 2.2 封包、密码与进程

| 用例 | 必须结果 |
| --- | --- |
| 计划内普通包 | 真实归档工具产生独立可解包文件；非固实/加密策略可核对 |
| 缺成员、额外成员、重复成员、损坏头、错误密码 | 验收失败，不以退出 0 或存在文件判完成 |
| 工具输出过多、非 UTF-8、提示等待密码、卡住 | 有界输出、可取消；进程树回收，Tk 不冻结 |
| 密码接口探针 | 测试口令不出现在进程参数、日志、文件清单、异常报告中 |
| 断电/退出发生于封包、校验、封存前后 | 半成品不伪装成 sealed；已封存包不可覆盖 |
| 新批次重试、同一命令重复 | 幂等或生成明确新代次，不混用摘要/目录 |
| 工具版本或可执行文件被替换 | 识别摘要/能力变化，暂停生产使用并重新验证 |
| 原生进程不能及时结束 | 报实际未退出状态，不假称关闭成功 |
| 电脑现有文件保护软件限制读写 | 如实失败，不改保护软件设置；跨程序字节差异能被检测 |

密码材料从独立恢复位置取用，关闭原会话后仍应能解开测试包。只验证当前进程记着密码不算灾后恢复通过。

### 2.3 回读与恢复数据

| 用例 | 必须结果 |
| --- | --- |
| 回读完整包 | 核对完整密文 SHA-256、全部成员及 manifest，记录时间和来源等级 |
| 只给原始包目录、硬链接或相同文件身份 | 拒绝自动当作远端回读；不改变云端证据等级 |
| 只有用户说上传成功/只有文件大小相同 | 保持待回读，不进入可释放 |
| 同名不同字节、截断、缺包、缺控制包、缺恢复文件 | 精确定位失败；完整组状态不能掩盖它 |
| PAR2 无损样本 | verify 通过，输出参数和有效恢复块数 |
| 随机局部损坏、头部损坏、分散损坏 | 修复能力以内恢复后完整摘要匹配；能力外明确失败 |
| 整组最大包删除，其他数据与恢复块保持完好 | `whole_largest_pack` 方案必须恢复并核对所有成员；这是资格门槛 |
| 部分恢复块也损坏、尾组不足 10 包 | 重新计算能力，不能沿用笼统 15% 承诺 |
| 纠错工具修复失败或输出错误文件 | 好包和原损坏副本保留，不直接替换正式资料 |
| 只保留包/控制资料，移走测试数据库与应用 | 按 RESTORE.txt 解密并重建目录，恢复指定作品 |
| 只有总目录损坏 | 通过各包 manifest 重建内容映射；不要求服务器再提供原图 |

所有破坏试验只作用于隔离测试副本。不得通过故意损坏正式归档、删除真实云端包或禁用保护软件来制造故障。

### 2.4 空间释放、数据库和下载接入

| 用例 | 必须结果 |
| --- | --- |
| 本地已主动释放且有完整归档证据 | 下载主线显示已归档，不重新取图；历史成功保留 |
| 历史已转存但无核验证据 | 维持未知等级，提示定位/核验，不自动补下 |
| 归档存在但位置变更或近期访问失败 | 保留旧证据，显示待复查；不误报本地齐全 |
| 核验后原图被改动 | 释放前识别冲突，保留新文件 |
| 路径/根/代次在释放前变化 | 旧计划不得执行，拒绝越界或过期结果 |
| 释放前、删除后提交前、提交后退出 | 逐文件幂等对账；无 evidence 不猜成功 |
| 根离线、磁盘满、权限失败 | 不把整根视为丢失；不自动删除其他资料腾空间 |
| 新 schema 副本迁移、失败回退 | 旧数据保留，未来/不兼容版本拒写；实际事务恢复通过 |
| 归档完成但导出失败 | 图片事实保留，释放前的必需目录/控制资料门槛仍阻止删除 |
| 磁盘不足且其他程序继续写入 | 重新测量并暂停，不突破保留余量 |
| 双实例、下载/封包同对象竞争 | 遵守单写/对象归属锁，无双重释放或重复计数 |

## 3. 性能测量

测量固定文件集、工具版本、参数、磁盘和缓存状态；含新下载的同时运行场景需单列。分别记录：扫描/复制/哈希/封包/解包/纠错的耗时、吞吐、峰值内存、磁盘峰值、UI 延迟、取消时间、日志容量和异常。

不为了速度关掉摘要/解包检查，不把低压缩和高压缩不同策略当同一质量的跑分。PAR2 记录块大小对修复粒度、CPU/内存和时间的影响。先小样再放大至目标单包及一组规模；预估不能代替实际峰值。

沿用 UI p95 ≤100 ms 的反馈目标，有界队列和日志规则。文件/工具系统调用可能阻塞时明确收尾状态；不得通过只测按钮响应宣称后台已安全停止。

## 4. 真实夸克小样操作卡

执行前交给用户的材料应包含：测试对象清单、总字节、推荐远端位置、回读目录、预计操作步骤，以及“原资料保留、这批不执行删除”的说明。测试不需要用户发送密码或 Cookie。

1. 程序生成普通测试图片/文件及独立包，记录原始与密文摘要；可以故意让一个恢复组包含多个小包来验证缺包保护。
2. 用户在官方客户端上传清单内所有对象；完成后记录远端路径与账号别名，状态为待回读。
3. 用户从该位置下载到独立的新目录，确认来源；程序验证它不指向原封包目录，再做完整内容核验。
4. 选择一个作品，从回读包恢复到新目录，逐文件匹配原始清单。
5. 在另一份离线副本模拟丢包/损坏，完成恢复演练；不对夸克正式对象做破坏。
6. 留存工具版本、观察时间、字节/成员数、全部失败、源等级和结果。只有本批实际通过的功能进入下一阶段。

网络/客户端问题记录后暂停，不循环重传，单次小样失败后先查明原因再继续。用户说流量充足允许做充分回读；不能据此无限重试、探测账号或重新下载整个图库。

## 5. 发布门槛

- 真实密码无泄漏通道，独立密钥恢复演练通过。
- 目标格式及工具版本已核验；不存在因为找不到工具就使用不明内置 WinRAR 的兜底。
- 所有成员匹配、归档独立、所宣称的纠错能力实际演练通过。
- 断电/取消/满盘/路径/双实例等关键异常通过。
- 已归档后主动删本地不会触发默认补下；真正未核验的状态不伪装完整。
- 已发布源版本有对应功能测试和本批证据；文档、状态表与界面一致。
- 没有未解释的源码/配置/业务数据变更；启动入口、旧资料和当前视觉方向保留。

未通过时按实际阶段停留，不用“基本完成”跳过释放门槛。实现期间每批执行相关测试，已通过且无新变化的检查不无意义重跑。
