## 1. 用户已确认的事实

| 事项 | 当前结论 | 依据 |
| --- | --- | --- |
| 本地删图原因 | 上传网盘后主动腾空间，不应默认判为意外丢图 | 用户：“丢图是我自己删的。因为我硬盘空间不够” |
| 保存目的 | 长期留档，以后能找回原件；当前不常看也要保留 | 用户希望类似“永冻库”的留档 |
| 当前网盘 | 夸克，SVIP；没有第二个网盘或移动硬盘副本 | 用户本轮说明；本轮未登录核验 |
| 图库规模 | 约 500 GB | 用户估计；尚未盘点其本地/云端分布 |
| 临时空间 | 常态约 100–200 GB | 用户估计；执行时仍要检查目标卷实时余量 |
| 网络流量 | 不是主要约束，用户愿意配合回下载验证 | 用户：“我不缺流量，我们有很多流量” |
| 内容隐私 | 收藏可能含成人内容，希望私人保存 | 加密保护隐私，不承诺绕过平台规则或永久可访问 |
| 当前授权 | 已授权分批实现；本轮任务为 A1 离线修复与验证 | 本轮不实施批量上传、删除、安装或生产迁移 |

这份记录只保存需求，不记录账号、密码、作品标题或私密样图。对网盘可靠性的风险偏好按用户选择保留，不把第二个网盘作为首版使用前提；单一远端仍不是独立多副本。

## 2. 现在需要用户做什么

**暂时不需要下载全部 500 GB，也不需要提供密码。**

先完成离线封包与恢复验证。真实小样开始时，再请用户用夸克官方客户端上传并取回专门测试包，选择新的本地回读目录。初次约几百 MiB 至 2 GiB，原件和现有云端资料全部保留。

只有当测试、工具来源、密钥保管和明确的空间释放条件通过后，才处理实际收藏的一个小批次。已经只在云端的旧图按需小批下载，不先全量搬回或重新打包。来源没有历史摘要时，只能建立当前观察基线，不能事后证明与最初 Pixiv 下载字节完全相同。

## 4. 推荐方案与首版范围

建议在 JpgPng 内增加轻量归档模块，复用现有 Python、SQLite 写入边界、相对路径和 Tk 风格。首版用官方夸克客户端人工传输；JpgPng 负责计划、文件清单、封包证据、回读检查、归档位置和恢复记录。

| 参数 | 设计起点 | 性质 |
| --- | --- | --- |
| 独立包目标 | 2 GiB 左右，按完整文件/作品边界调整 | 起点，不是夸克上传上限 |
| 每批原始输入 | 至多约 20 GiB；空间不足自动缩小计划 | 容量控制，不默认填满硬盘 |
| 普通输出格式 | 候选 7z，AES-256、文件名加密、非固实，存储或低压缩 | 工具与安全密码通道通过后才发布 |
| 图片处理 | 原始字节保存，不转码、不重存图片 | 硬要求 |
| 恢复数据 | 默认方案候选：每组至多 10 个包，PAR2 起点 15% | 必须按块数验证目标，比例本身不保证修复 |
| 核验 | 每个归档包、恢复对象、控制包均完整回读；每个包验证解包及成员摘要 | 不用抽样代替首次验收 |
| 原图释放 | 先生成具体清单，用户执行这一批释放动作 | 不随上传结束自动删图 |
| 周期复核 | 显示上次回读时间与到期提醒，人工启动 | 首版不添加后台云端定时任务 |

2 GiB 是二进制单位；用户的 500 GB 是约数，不据此预先生成精确包数。封包与恢复数据会额外占用网盘空间，试验前确认实际剩余容量。

现阶段优先选成熟封包/纠错实现，不自研密码算法、压缩格式或 Reed-Solomon 编码。7z 提供 AES-256 和不压缩存储方式；PAR2 支持检查和有限损坏修复。[7z 官方格式](https://www.7-zip.org/7z.html)、[PAR2 官方项目](https://github.com/Parchive/par2cmdline)

## 5. 对原优化设计的修订

| 原建议 | 当前调整 |
| --- | --- |
| U1-A 优先做缺失核验/补齐 | 优先做归档接纳、回读验证、位置索引和明确空间释放；真正缺失再进入修复 |
| 每批已有页优先检查本地文件 | 先查询保存形态：本地、已归档、已转存未核验、未知；已归档页不要求每次下载主线都从云端取回 |
| 本地不存在可列缺失 | 有归档证据和主动释放记录时显示“已归档，本地已释放”；无证据不猜已归档，也不自动重下 |
| 历史成功与当前文件健康分离 | 保留这一原则，再加独立的归档/恢复证据 |
| gallery-dl 接入试验 | 保留研究，优先级后移；当前没有选定新引擎 |

原图交付、筛选和覆盖的审计问题没有因此消失；共用依赖维护仍是独立事项。归档字节完整不能把结构级图像检查提升成深解码，也不能把来源不完整变成画师作品收全。

## 6. 非目标和现实边界

- 不要求一次取回 500 GB，不整理或清理其他项目。
- 不更换当前下载入口，不增加缩略图、Node、Web 服务或本地模型环境。
- 不在首版逆向夸克登录/上传接口，不导出浏览器 Cookie，不提供“永久不封”保证。
- 不把打包完成、上传界面完成、文件大小相同、压缩工具退出 0 当成全部验收。
- 不因选择了一个目录就递归删除其中所有内容；业务清理只针对通过条件且身份一致的显式文件清单。
- 不把同一夸克账号里两份目录或恢复数据叫作两个独立备份。平台整体不可访问超出该单站方案的恢复能力。

夸克协议对私人存储也有规则并保留相应限制权；首版不以会员、加密或不分享作为不受限承诺。[官方协议](https://terms.alicdn.com/legal-agreement/terms/c_platform_service_agreement/20260130142844546/20260130142844546.html)
