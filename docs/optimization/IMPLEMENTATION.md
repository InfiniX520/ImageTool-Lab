## 3. 一套语义与历史保全

- 历史下载成功保留；当前本地状态、归档证据、来源质量、作品覆盖和用户意图独立。
- 用户主动移除、已核验归档、历史转存未核验、真正未知缺失分别处理；不默认补下载。
- 严格摘要核验与快速属性检查不同；归档可用不表示本地文件还在。
- 原图字节优先、性能其次；下载无缩略图、相对路径、少依赖，沿用白蓝 Tk 入口。
- 原[优化三稿](2026-11-11/README.md)与[归档四稿](../archiving/README.md)继续承载详细设计。旧稿中的“当前状态/下一步”是当时快照，当前排期以本页、机器计划和最新日志为准。
- 老 schema 和旧任务策略不能被静默重标。实现统一迁移前只使用合成数据与临时库，不改生产数据库。

## 4. 已完成批次：JPGPNG-UNIFIED-IMPLEMENTATION-20261111-01

### 代码交付

新增 [preservation_policy.py](../../core/preservation_policy.py) 和 [行为测试](../../tests/test_preservation_policy.py)。纯判断模块不读写磁盘、不联网、不导入到旧下载启动链，不进行文件删除。

- `ContentVersion` 明确资产/代次/大小/可选历史 SHA-256。
- `LocalEvidence` 绑定内容、路径、根映射版本和本次核验标识。其他任务/位置/代次的观察被忽略；完整摘要一致才接受 `hash_match`。
- `ArchiveEvidence` 区分用户报告上传、人工取回核验、适配器取回核验和访问失败。它引用将来的真实验证记录；构造对象不证明真正经过云端。
- `PreservationPolicy` 第 1 版区分严格/快速，以及“已有保存副本”/“需要本地副本”。
- `assess_preservation` 返回复用、已归档跳过、待核验、冲突、访问待处理、可选择恢复、转存未核验或定位缺失等结果。它不调度补下载、不批准原图释放。

同一内容的云端证据可在本地路径迁移后继续保留；本地观察必须匹配当前路径和核验轮次。用户自行删除已归档文件时，不要求伪造程序执行的释放事件才能识别已保存副本。新改动文件优先保留为冲突，不因存在旧归档就覆盖。
